## 1. Product definition

**Fusion Shell** is a **paid Android app suite** that turns any Snapdragon-8-class (or equivalent) Android phone/tablet into a complete desktop environment — Windows/macOS-class in function — on the device screen and on an external monitor, with mouse/keyboard, using all available hardware (CPU cores, GPU, hardware codecs, NPU, DisplayPort Alt Mode, USB OTG, Bluetooth, Wi-Fi), **without root** and **without replacing the OS**.

**It is:** a Home-role launcher (opt-in), an in-app window compositor, a first-party app suite (files, browser, editor, office/Forge, media, terminal, notes, capture, vault, backup), a service layer (index/search, file-ops, alerts, casting, continuity), and a hardware/performance governor.

**It is not:** a kernel, ROM, driver, OS updater, keyguard, TalkBack replacement, or a way to run macOS apps. Windows-app compatibility is an optional later module.

### 1.1 Personas (priority)
| ID | Persona | Needs |
|---|---|---|
| PA | Dock-and-dev power user | terminal, files, palette, tiling, automation, backup, monitor+keyboard |
| PB | Pocket-PC knowledge worker | browser (desktop-class), Office docs, notes, alerts triage, sharing |
| PC | Creator / media / presenter | capture, media, **AirPlay/Cast to TV**, PSD/HEIC handling, sustained perf |

## 2. Platform & device baseline

### 2.1 Supported hardware floor (DEV-01, replaces any single-device framing)
```
SoC        : Qualcomm Snapdragon 8 Gen 1 or newer (8/8+ Gen 1, 8 Gen 2, 8 Gen 3,
             8s Gen 3, 8 Elite and later) — or equivalent-class SoC
             (Tensor G3+, Dimensity 9200+, Exynos 2400+) via capability probe
RAM        : ≥ 8 GB   GPU: Adreno 730+ (or equivalent)   ABI: arm64-v8a only
Android    : ≥ 14 (API 34)   compileSdk 37   targetSdk 36 → 37 at M7
Display out: USB-C DisplayPort Alt Mode — supported capability, NOT a requirement
             (silicon-level since SD835 [W-prior]; OEMs may disable → probe)
Page size  : 4 KB and 16 KB both supported (native libs 16 KB-aligned)
```
Reference devices: A = SD 8 Gen 3 phone (e.g., ROG Phone 8 Pro, Android 16), B = Samsung Galaxy S24/S25 (One UI, DeX), C = Pixel 9/10 (Android 17, stock desktop windowing). Record `ro.build.fingerprint`, `ro.hardware.chipname`, RAM, DP-out, display modes before every measurement.

### 2.2 Platform facts carried forward [W-prior]
- Android 17 (API 37): removes app opt-out of resizability on ≥600 dp (incl. desktop mode); per-display desktop windowing; Handoff APIs; memory limiter (`am memory-limiter`); native libs passed to `System.load` must be read-only; `ACCESS_LOCAL_NETWORK` required for LAN at target 37; NPU needs `FEATURE_NEURAL_PROCESSING_UNIT`; contact picker; EyeDropper; AppFunctions alpha.
- Android desktop mode (stock) is glitchy [W-prior]: mouse-back unmapped, oversized panels, no desktop pinning/widgets, phone screen stays on (burn-in), focus-stealing collapses session, settings shared between phone/desktop, no MDI, no drag across desktops. **Hence H1 (our compositor) is the mandatory primary host.**
- Compose-first (Views in maintenance); Compose 1.11 adds trackpad/mouse support and focus rings.
- Play: new apps/updates must target API ≥36; developer verification rolling out; ADB sideload exempt.

### 2.3 SDK decision (BUG-03 fixed rationale)
minSdk **34** because: Credential Provider API, predictive back, per-app language, foreground-service type declarations, photo-picker improvements. Lower minSdk is a recorded trade (reach vs. API loss).

## 4. Design principles (DP) and UX rules (UX) — consolidated

**DP-01** local-first, account-free · **DP-02** no ads/feeds/upsells anywhere · **DP-03** explicit data semantics (local/synced/online-only/backup/snapshot/archive labeled) · **DP-04** no silent state mutation · **DP-05** reversible by default (undo/trash/rollback) · **DP-06** keyboard-complete · **DP-07** accessibility is a release gate · **DP-08** measured performance, not claimed · **DP-09** isolation of untrusted parsing/terminal/web in separate processes · **DP-10** capability honesty (probe, degrade visibly) · **DP-11** least privilege, prompt-light · **DP-12** respect system defaults/pickers · **DP-13** progressive disclosure via density profiles, never hidden capability · **DP-14** every background job observable.

**UX-01…UX-20** as in v1.0 (no silent mutation; destructive-action preview; Copy≠Move; sync≠backup; visible dismiss; app/window switcher modes named; context menus concise/full/custom + type-to-search; search provenance & local-first; one settings entry per behavior; keyboard alternative for every pointer op; no promotions; just-in-time permissions; progress at 250 ms, cancel ack ≤100 ms; hover/focus always visible; reduce-motion respected; plain-language errors; account-free first run; undoable settings; session restore after crash; shortcut conflict detector).
**UX-21** system panels on external displays ≤400 dp wide and ≤70 % height. **UX-22** every document module supports tabbed AND windowed MDI. **UX-23 (new)** any cast/AirPlay session shows a persistent, one-click-stop indicator with target name, codec, latency, and what is being shared (screen / app audio / file).

**Density profiles:** Compact (24 dp targets, 28 dp title bar; mouse+monitor), Balanced (32/36), Touch (48/48). Profiles change size, never capability.

**Naming (trademark-safe):** Launcher, Shelf, Top bar, Files, Find, Overview, Workspaces, Tiles/Groups, Quick panel, Alerts, Peek, Timeline backup, Send, Vault, **Beam** (casting hub), **Together** (synchronized sessions), **Forge** (format engine).

**Shortcut presets:** Hybrid (default), Windows-like, Mac-like — table unchanged from v1.0 §7.4; conflict detector mandatory; validated in S1.

**Accessibility (WCAG 2.2 AA mapping):** keyboard (2.1.1), focus visible (2.4.7), focus not obscured by floating windows (2.4.11 — compositor raises/scrolls), drag alternatives (2.5.7), target size (2.5.8), accessible auth (3.3.8), reflow at 200 % (1.4.10), name/role/value (4.1.2). TalkBack, Switch Access, Voice Access pass lists are gates.

### 5.3 Gradle modules

### 5.4 Window engine (pure Kotlin)
Immutable `DesktopState`; reducer `(State, Command) → State` pure/deterministic; side effects emitted separately. **Invariants:** ≥48 dp of title bar always on-screen; min window size 240×180 dp (Compact) / 320×240 dp (Touch) [BUG-06]; z-order total; commands idempotent; state versioned/serializable. Rendering: one Composable per window; position/size via layout/graphicsLayer lambdas (no content recomposition on drag). Persistence debounced ≤1/500 ms to Room; restore after death/reboot. Semantics: each window a pane with title + custom actions (move/resize/tile/close). Tests: JVM property tests, screenshot tests, Macrobenchmark drag/resize. Data model in Appendix C.2.

### 5.5 Capability Probe (run at start, display change, permission change, on demand)
Outputs: sdk, fingerprint, freeform feature, desktopSessionActive (nullable), displays (+DP-out, modes/Hz), homeRoleHeld, overlay, notification listener, all-files, usage access, Shizuku, RAM class, thermal status, page size, NPU declared, non-protected VM, **HW codec list (AVC/HEVC/AV1/VP9 enc+dec, max res/fps)**, **AAudio low-latency flag**, **Vulkan version**, **local-network permission**, **cast targets discoverable (mDNS/SSDP allowed)**.
Behaviors: desktop session → offer H2; freeform missing → broker S2/S3 labeled; all-files missing → SAF-only banner; listener missing → setup card; overlay missing → no return overlay; thermal severe → pause index/backup/cast-encode-quality-drop; low RAM → RG-07; no HW HEVC encoder → cast uses AVC; no DP-out → "desktop on phone screen" mode.

### 5.6 Index & search
Room FTS4 (platform) or FTS5 (bundled driver, if S4 passes); trigram fuzzy; sources: apps, settings registry, contacts/calendar (gated), MediaStore (generation numbers), files (scan+observers), notes, commands, **cast targets**; build only charging/idle, thermal-throttled; churn quarantine; health UI (coverage, last run, exclusions, errors, rebuild); index encrypted (Keystore-wrapped key); private folders excluded by default.

### 5.7 File-operation engine (state machine)
`REQUESTED → COPYING_TO_TEMP → DEST_VERIFIED → DEST_PUBLISHED → SOURCE_RETIRE → COMPLETE`. Cross-volume move = copy to temp → verify (size + optional hash) → fsync → atomic rename → retire source. Interrupt before publish: source authoritative; after publish: keep both, report "needs cleanup". Non-atomic SAF providers flagged before first move. Every transition journaled in Room; recovery at process start. Foreground service / user-initiated data-transfer job.

### 5.8 Backup engine (S7 decides)
A: packaged restic (BSD-2) executable from :svc (read-only libs, 16 KB) · B: Kotlin engine (content-defined chunking, Tink AEAD, documented repo format) · fallback B-lite (hash manifest + versioned copies). "Healthy" only after a verified sampled restore.

### 5.9 Notification pipeline
Listener → filter → store (Room, opt-in, 7-day TTL) → group/rank → UI. Never persist secret-visibility; clear on disconnect; rate-limit floods; PendingIntents stay inside the notification.

### 5.10 Extension model (P4)
Context-menu/preview/search extensions in isolated processes with time budgets.

### 5.11 Build policy
One version catalog; R8 full; Baseline Profiles + Macrobenchmark from M1; LeakCanary debug; Hilt, coroutines/Flow; no RxJava; no new Views; permissive licenses in main APK; SBOM in CI with license-diff gate; every export justified.

```

  office  : :format-lok (LibreOfficeKit, MPL-2.0, isolated)  — Grade A view/edit/save
            :format-poi (Apache POI, Apache-2.0, shaded)     — Grade D headless/batch
```

### 5.14 Beam — casting & AirPlay subsystem (new, verified landscape)

**Protocol facts (what exists in the open):**
- **AirPlay sender, audio (RAOP / AirPlay 2 audio):** pyatv (MIT) implements audio streaming to Apple TV, HomePod, and AirPlay receivers, plus remote control and `play_url` [W]. rust-atv (pure Rust port of pyatv) exists [W]. ⇒ A permissive clean-room Kotlin/C++ port is feasible (CA-01).
- **AirPlay sender, video-by-URL:** receivers play a URL supplied via the AirPlay HTTP `/play` interface; pyatv's `play_url` works on tvOS 15+ (MRP now tunneled over AirPlay 2) [W]. ⇒ Our media files/streams can be served from an in-app HTTP server to Apple TV (CA-02).
- **AirPlay sender, screen mirroring:** needs sender-side FairPlay; an open project (open-airplay, Windows) claims this was "the piece open source had never cracked" and that only paid tools did it [W]. License/legal status of that code is **unverified [U]**; FairPlay is Apple's DRM → **do not vendor**; clean-room implementation must be legally reviewed (CA-04, Pro flavor, gated).
- **AirPlay receiver on Android:** `android-airplay-server` = UxPlay-based (UxPlay is **GPLv3**) with MediaCodec/ALAC decoding, first open AirPlay 2 receiver for Android/Android TV [W]; PhairPlay = AirPlay 2 + Miracast + Google Cast receiver with FairPlay decryption via libplayfair [W] (license [U]); `shairport-android` = Shairport Sync (MIT [K]) + NQPTP (GPL [K]) cross-compiled, AirPlay 1 & 2 audio receiver [W]; `airplay-tv` = Kotlin AirPlay mirroring receiver for Android TV with RTSP/pairing/FairPlay core [W] (license [U]). ⇒ Receiver ships as a **separate GPL-licensed APK** (`Fusion Beam Receiver`) or as our own clean-room core (CA-06/CA-07).
- **Google Cast sender:** Cast Application Framework SDK — free, Google terms, not OSS; Default Media Receiver needs no console registration; custom receiver requires a Cast Developer Console app ID (small one-time fee) [K]. Open protocol (castv2: protobuf over TLS :8009) has MIT implementations in other languages [K] → own Kotlin client possible (CA-08). Screen mirroring to Chromecast via Cast SDK is not available to third-party apps; alternative = our own web receiver + WebRTC (CA-09).
- **Miracast sender:** no public API; open `Settings.ACTION_CAST_SETTINGS` (Tier C).
- **DLNA/UPnP:** permissive own implementation (SSDP discovery, AVTransport SOAP, in-app HTTP server) — Cling/jUPnP are LGPL/CDDL → not in main APK (CA-10).
- **"Android SharePlay":** does not exist natively; Google offers Meet live sharing (proprietary). Build **Together** on libwebrtc (BSD) + our signaling over LAN/relay (CA-11); use Android 17 Handoff for continue-on (CT-03).

**Beam protocol notes for the coder [K unless tagged]:**
- RAOP: mDNS `_raop._tcp` TXT (`et`, `cn`, `tp`, `sf`, `pw`), RTSP OPTIONS/ANNOUNCE (SDP with ALAC fmtp, RSA-encrypted AES key for AirPlay 1 receivers that require it)/SETUP (ports: server, control, timing)/RECORD/SET_PARAMETER (volume, metadata, artwork)/FLUSH/TEARDOWN; RTP audio 352 frames/packet; NTP timing packets; sync packets each second. AirPlay 2 audio adds HAP pairing (SRP + Ed25519/X25519 + ChaCha20-Poly1305) and PTP timing — port pyatv's `raop` and `airplay` modules behavior [W]. 
- AirPlay video URL: `_airplay._tcp`, HTTP `POST /play` with `Content-Location` + `Start-Position`, `/scrub`, `/rate`, `/stop`, `/playback-info` polling, `/reverse` event channel; tvOS pairing/`auth-setup` as needed.
- Mirroring: RTSP over `_airplay._tcp` port 7000 with `/fp-setup`, `/pair-setup`, `/pair-verify`, SETUP streams (type 110 video, 96 audio), H.264 Annex-B in a length-prefixed framing on the mirror TCP stream, stream-encrypted with FairPlay-derived AES — **the FairPlay step is the legal/technical blocker** (CA-04).
- castv2: TLS to :8009, `CastMessage` protobuf, namespaces `urn:x-cast:com.google.cast.tp.connection`, `.heartbeat`, `.receiver`, `.media`; `LAUNCH` receiver `CC1AD845` (Default Media Receiver); `LOAD` media with contentId/contentType/streamType.
- DLNA: SSDP M-SEARCH `urn:schemas-upnp-org:device:MediaRenderer:1`, fetch device XML, `SetAVTransportURI` + `Play`.

# PART 2 — Fusion Lens: camera/mic prefilter + mobile presenting (new subsystem)

## 2.1 Formal model (abridged)

**Admissible objects:** a video/audio processing pipeline running on device, fed by the physical camera/mic (and screen via MediaProjection), producing a processed stream consumable by (a) a Fusion-owned conferencing client, (b) web conferencing pages inside Fusion Browser, (c) a PC companion as a webcam, (d) local record/RTMP. Only platform services + permissive OSS + our code.

**Success (quantifier order):** For **each** output route R ∈ {own client, web page, PC companion, record}, **there exists** a path such that processed video ≥ 720p30 (Standard) / 1080p30–60 (Studio) reaches R with glass-to-glass ≤ 120 ms added latency, and screen-share/present is available on the same route. For native third-party Android apps the predicate is **declared unsatisfiable** (below) and the UI must say so.

**Boundary that decides everything:** a normal app **cannot** register a virtual camera visible to other apps. Creating virtual devices requires `CREATE_VIRTUAL_DEVICE`, which is only available to system apps holding specific roles [W]; Android 17.2 exposes `isVirtualCameraSupported()` but behind the same system-level service [W]; system cameras are signature-protected and third-party public apps can't access them [W]; the only third-party route today is root/LSPosed-class injection (VCAM) [W], which is outside our product. **Hence H∂:** NVIDIA-Broadcast-class processing is fully achievable, but the *delivery* is per-route, never system-wide.

**Adjacent problems not to substitute:** "beauty filter in our camera app" ≠ prefilter for conferencing; "works in Meet web" ≠ works in Zoom Android app; "background blur" ≠ generative scene; "eye-contact GAN" ≠ gaze-aware framing.

## 2.2 Frontier (verified)

- Segmentation/landmarks: MediaPipe is free (Apache 2.0) and works on Android (C++ or ML Kit), WebAssembly, and TensorFlow.js [W]; the Selfie Segmentation model is lightweight (~250 KB) and licensed Apache-2.0 for commercial use [W]; Qualcomm AI Hub ships the same model, license Apache-2.0 [W]. MediaPipe Face Landmarker gives 3D landmarks and blendshape scores in real time [W]. Browser-side, MediaPipe Image Segmenter on WebGPU composited through a WebRTC Insertable Stream is the standard 2026 web blur architecture [W] — directly reusable for route (b).
- Phone-as-PC-webcam is an established pattern: the phone does Camera2 capture + OpenGL processing + RTSP; a PC-side Softcam DirectShow filter makes Zoom/Teams/OBS see it as a physical webcam [W].

# PART 3 — iMessage: what is permissible

**Question:** can Fusion do iMessage under the "permissive OSS, commercially free" constraint?

**Verified landscape:**
- **BlueBubbles** (client Apache-2.0 [W]; server Apache-2.0 [W]) brings iMessage to Android by relaying through the user's own Mac; it requires a Mac and an Apple ID; a macOS VM can suffice [W]. Features include texts/media/location, tapbacks, read receipts, replies, group management; private-API features add typing indicators and reactions [W].
- **OpenBubbles** (app fork Apache-2.0 [W]) runs iMessage on-phone via **rustpush**, but rustpush is **SSPL-1.0** [W] (not OSI-open, not permissive → **inadmissible**), building requires private Apple FairPlay certificates held by the maintainer; without them the app cannot register with Apple [W]; Apple requires hardware info from genuine Apple hardware, and a Mac cannot register your Android number [W]; accounts can be throttled or, rarely, blocked [W].
- **RCS alternative:** on Android only Google Messages can access the RCS API [W]; as of 2026 it remains the only RCS client [W]; Google does not offer the RCS API to third-party developers [W].

**Decision (H∂):**

| Path | Admissible? | Spec disposition |
|---|---|---|
| **MS-01** Fusion Messages module acting as a **BlueBubbles-API-compatible client** (own Compose UI; Apache-2.0 protocol/client code may be reused with attribution) connected to the **user's own Mac** running BlueBubbles Server | **Yes** | Tier A/B, P3. Requires user-owned Mac + Apple ID; label honestly; no cloud relay by us. Also yields FaceTime-link handoff only (no native FaceTime). |
| **MS-02** On-phone iMessage without a Mac (rustpush/pypush lineage) | **No** | SSPL license, private FairPlay certs, Apple ToS/ban risk → **X**. Document in negative space. |
| **MS-03** Hosted relay sold by us | **No** | Apple-account impersonation risk; conflicts DP-01; legal exposure → X. |
| **MS-04** RCS | **No (platform)** | No third-party API; Tier C: deep-link to Google Messages; shelf badges via notification listener. |
| **MS-05** SMS/MMS native (SMS role) | **Yes** | Tier B, P3; desktop-class SMS/MMS in Fusion Messages. |
| **MS-06** Open protocols: Matrix (Apache-2.0 SDKs), XMPP, Signal (AGPL → X), Telegram (API ok, clients GPL → own client) | **Yes (Matrix/XMPP)** | Tier A, P3/P4; Matrix also powers Together chat and Fusion Meet signaling. |

**Honest product line:** "iMessage on your desktop — with your Mac." Not "iMessage without Apple hardware."
