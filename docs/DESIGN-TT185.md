# TT185 — browser-origin quota timeout

## Runtime and model
One coding agent used repository source, Bash, Node/TypeScript/Next, ESLint, Git/GitHub CLI, an actual Chromium 143, disposable PostgreSQL, Python and independent external test libraries, and web search/fetch. No independent agents, theorem prover, or simulator were used. Tests inject delayed/rejected browser API promises to exercise fault paths; these are test faults, not claimed real disk or network events. Browser tests use an exclusive disposable server and database. Two CPUs were available; execution was sequential where DB-mutating tests share state.

Admissible object: the `VolumePanel` origin quota presentation in Files and Monitor, not a device capacity API or a filesystem mutation. Information available: `navigator.storage.estimate()` may be absent, throw/reject, return partial data, resolve, or remain pending. Resource: elapsed event-loop time in milliseconds, not CPU or server quota. Conditional success: for each mounted panel under an executing event loop, after a pending estimate's 5,000 ms timer callback runs, report that origin usage and quota are unknown; if it subsequently resolves or rejects, display that actual result or failure, respectively; on cleanup do not update that unmounted panel and clear its timer. If it resolves before the timer, the timeout must not overwrite it. Browser scheduling may delay the callback; no hard real-time bound, guaranteed settlement, physical disk capacity, platform-wide correctness, or autonomous retry is claimed. Scope does not include system device grants, storage persistence, writes, or durability.

H+: a bounded UI waiting state with genuine late-result recovery is achievable under a running event loop. H−: a web page cannot derive actual physical free-disk space from an origin quota alone, and a timer cannot establish a result for an unresolved API call. H∂: background throttling, suspended event loops, API availability, browser implementation and delayed responses alter timing/outcome. Evidence threshold: prepatch red case, production build, changed-file lint, real-browser/DB postpatch tests in both hosts, temporal stale-timeout and late-success/late-failure attacks, relevant carried regression suites, and honest disclosure of full-gate outcome. These are finite examples, not a Class-A proof.

## Frontier and six candidate mechanisms
[MDN](https://developer.mozilla.org/en-US/docs/Web/API/StorageManager/estimate) describes estimate() as an asynchronous secure-context API giving approximate origin usage and quota in bytes, not exact values; it may throw TypeError for an opaque origin or disabled storage. This is a platform boundary, not an impossibility theorem for every other API. [WAI disclosure pattern](https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/) specifies button state and Enter/Space behavior for a disclosure; it does not prove the existing Files layout is accessible. No best-possible liveness or accessibility theorem was found. Open interface: actual browser scheduling and storage availability across engines, plus accessible notification and retry semantics.

1. **Timer + late completion (implemented)**. Artifact `VolumePanel` and `e2e-tt185-quota-timeout.mts`. Before patch, three held-promise tests failed with perpetual reading; postpatch held/late paths are browser-tested. Attacker: late failure and stale timeout after prompt success. Gap: event-loop suspension and unmount race, local; no deadline for a synchronously blocking API.
2. **Promise.race with timeout**. Design: settle UI at deadline and ignore subsequent resolution. Counterexample: an actual late response is thrown away, leaving unknown even after information arrives. Cheapest attack: resolve held estimate after deadline. Gap is local recovery semantics, not global OS completeness; not adopted.
3. **AbortController**. Design would abort an abort-aware request after deadline. Counterexample: estimate() has no documented signal parameter; abort cannot be assumed to stop it. Cheapest test: inspect API signature and hold the promise. Gap local, not adopted.
4. **Manual retry**. Design: user requests another estimate, with epochs to reject stale earlier results and explicit in-flight state. No implementation in this turn; attacker: two concurrent attempts resolving out of order or after unmount. Requires concurrency tests; gap local.
5. **Periodic polling**. Design: schedule repeat estimates and surface timestamp/unknown on failure. Counterexample: extra background work and overlapping calls under suspension may cost resources or show stale data. Cheapest attack: hold all requests and count concurrent calls. Gap local scheduling/privacy; not adopted.
6. **Disclosure or controlled density fixture**. Candidate: keep examples discoverable on request; separately measure fixed chrome and variable rows under controlled datasets with clipping-aware checks. Artifact is TT184's density diagnostic and WAI disclosure reference; no implementation/claim. Attacker: inaccessible closed control or false pass from hiding real functionality. Gap local but needs screen-reader, geometry and populated-data validation.

## Fifteen misleading shapes
Build success is not feature acceptance; a fixed example is not a real volume; origin quota is not disk free space; an estimate is not exact; a timer is not cancellation; a deadline is not a real-time guarantee; a pending promise is not proof of failure; a late success is not proof of earlier success; a simulated rejection is not evidence a real browser rejected; a missing API is not zero quota; one Chromium fixture is not all browsers; keyboard-only checks are not full accessibility; a density cap is not visual usability; a register label is not Class A; a longer gate is not a Pareto speedup. Modal shortcut: treating a plausible placeholder or the word “reading” as a real, completed measurement. The held-promise browser test detects an indefinitely unresolved display, and the late-result test detects throwing away later real information; neither proves universal behavior.
