# TT179 — verify real browser cancellation and Backup parent race

## Model and thresholds
Objects: the production browser lane (`gate-child.sh`, gate, Playwright real Chromium) and the Backup panel's real mkdir/create sequence on an exclusive disposable PostgreSQL database. Adversary can stop the helper after a real browser starts or trash the folder after mkdir commits and before the guarded write; requests may be concurrent or lost. Observables: process/session identifiers, VFS identity/trash flags, UI warning, HTTP statuses; no speed claim. For each tested race, a trashed parent must not be revived or written into, and failure must be reported; for cancellation, observed actual browser processes must not continue executing following the stop. This is bounded empirical evidence, not quantification over all OSes, child processes, concurrent schedules, total OS completeness or Class A. Pre-commit threshold: real counterexample on old helper if present, final actual Chromium/process cleanup attacks and real browser/HTTP/DB parent race, related regressions and honest gate status.

H+: a bounded graceful cleanup may stop the actual browser while preserving process-group isolation. H−: descendants in their own sessions need not receive a group signal, so the existing KILL-only implementation cannot guarantee cleanup; whether this real Chromium leaks must be measured. H∂: SIGKILL, SIGTERM handling, detached processes, OS and abrupt failures change behavior; process trees and external effects cannot generally be assumed cleaned up. No proof for all browsers or hardware. Tools: local shell/git/gh, Node/TypeScript, Next build, Playwright real Chromium and disposable PostgreSQL, web search; no independent agents, theorem prover, simulator, human/AT expert or physical receiver. Existing full gate failed as recorded in TT178; must not treat a targeted pass as a full pass.

PostgreSQL READ COMMITTED permits `INSERT ... ON CONFLICT DO NOTHING` to skip an insertion because of a concurrent transaction not visible to its statement snapshot, assuming the relevant unique constraint and no unrelated error (https://www.postgresql.org/docs/current/transaction-iso.html). This does not guarantee HTTP delivery or cover separate mkdir/write transactions. Node documentation notes that a detached Unix child is a new process group and session (https://nodejs.org/api/child_process.html#optionsdetached). Neither statement establishes application-level exactly-once or universal child cleanup. The open interface is actual browser cleanup under cancellation and cross-request folder consistency, not a global OS optimality theorem.

## Candidate mechanisms and adversaries
These are distinct candidate contracts, not six verified fixes; gaps are local to runner or Backup unless noted.
1. **Group SIGKILL immediately**: TT178 helper artifact. Real Chromium child in a separate session was still executing after cancellation; the real test failed. Local detached-child gap.
2. **Bounded TERM then group KILL**: implemented helper sends TERM to the actual suite group, lets Playwright close its detached browser, escalates after three seconds, and kills remaining same-group processes. Real Chromium cancellation and process attacks are rerun; an independently detached or uncooperative browser can still survive if the suite cannot close it, and SIGKILL cannot be trapped. Local lifecycle gap.
3. **Direct browser process-group kill**: design locates browser PID/session and kills that group. Attacker launches multiple browser contexts or PID reuse; test actual concurrent browsers. Not implemented; safe ownership identification is unresolved.
4. **Enumerate process descendants**: design repeatedly walks `/proc` then kills descendants. Attacker forks, reparents, changes sessions or causes PID reuse; test rapid fork/session changes. Not implemented; TOCTOU gap.
5. **Cgroup per suite**: design confines descendants regardless of process group. Attacker has privilege to escape or platform lacks cgroup delegation. Test an actual detached Chromium in a delegated cgroup. Not implemented; infrastructure/portability gap.
6. **Do not stop suite**: design waits for ordinary completion. Attacker hangs indefinitely or user cancels; test TERM-ignoring real process. Not implemented; local availability gap.
7. **Backup mkdir then guarded create**: implemented prior turn; attacker trashes folder exactly after the first commit. This turn forwards an actual create after trashing through real API; tested result must be conflict with parent left in Trash and no child. Remaining gap: not a single transaction or exactly-once recovery.
8. **Atomic mkdir/create server transaction**: design binds parent validation, creation and guarded insertion together; attacker races tree operations and unrelated VFS writers. Test real PostgreSQL concurrency. Not implemented; shared VFS/API gap.

## Negative space and modal shortcut
A killed shell is not a killed timeout; killed group is not a killed detached browser; successful signal delivery is not process exit; a zombie is not an executing browser; exit status is not complete fixture cleanup; a child closed by Playwright is not every subprocess in every failure mode; three-second escalation is not an absolute OS scheduling bound; SIGTERM handling is not SIGKILL handling; one browser model is not all browsers; a timeout is not proof of deadlock; a fixed request order is not concurrent safety; a folder ensure is not a file commit; HTTP network failure is not proof of rollback; a 409 is not a unique collision diagnosis; one target identity is not a batch snapshot; data left in Trash is not secure erasure; passing targeted suites is not the full gate; an authored label is not Class A; screenshot is not all-app accessibility; wall time alone is not Pareto superiority. The modal shortcut was killing only the suite's process group: the actual Playwright Chromium had a different process group/session, and a real PID test showed it still running. The repaired helper was retested against actual Chromium; this is not a universal cleanup proof.

## Results and remaining risks
Before repair, real headless Chromium PID was still executing after cancellation; the adversarial test failed. After bounded TERM then group KILL, actual Chromium test passed, and TT178 real-process suite was rerun. A real browser/HTTP/disposable PostgreSQL test trashed the Backup parent between committed mkdir and guarded create: the folder stayed trashed and no child was written; fresh DB suite passed 5/5 including prior attacks. No app UI change or 20 Class-A promotions this turn. Fresh-database test remains intentionally separate from shared gate and requires an explicitly initialized disposable DB.

The helper cannot guarantee cleanup of a browser that ignores shutdown, escapes its process group, or survives the suite being killed before graceful cleanup. Three-second escalation can leave temporary orphaned sleep/watchdog processes; process ID reuse and whole-tree cleanup remain unproven. Interrupted tests may leave database mutations. Same-minute backup copies are still refused, and mkdir/create remains two transactions. No performance benchmark, all-app visual survey, independent agent, theorem prover or expert review.
