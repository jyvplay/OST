# TT210 — retain gate process-group identity until signalling

## Contract, hypotheses and tools
Admissible objects: a Linux Python supervisor, its `start_new_session` child running GNU `timeout`, that child's original process group, and cooperating same-user gate suites. The supervisor is the child's only reaper; SIGCHLD is not ignored and no external debugger/reaper interferes. It can signal its group, execute `ps`, and inspect the process table visible in its PID namespace. Resources: one supervisor and one leader per active suite, wall time in ms, supervisor polling every 20 ms, up to 50 process-table scans with a 2 s per-`ps` timeout; real elapsed time can exceed 1 s. Success for every tested case: every negative-PGID signal precedes reaping the identified child, and the helper preserves exit/status and does not report success when observed cleanup cannot be confirmed. The signal identity argument depends on Linux PID allocation and the leader remaining unreaped; table validation is not proof of unrestricted visibility. Failure includes signaling after reap, false successful inspection, or a runnable observed same-group fixture child after exit. Cancellation gives the suite up to 3 s if its leader remains alive; a leader that exits sooner triggers cleanup immediately. Distinct problems not solved: descendants escaping sessions, SIGKILL of the supervisor, inaccessible processes, credential changes, malicious `ps`, a kernel D-state task, strict bounded completion under all schedules, child-process resource cleanup, portability, and app-wide Class A.

H+: pinning the leader until after group signalling avoids the identified reuse window for the stated model. H−: even a pinned process group cannot guarantee cleanup of arbitrary detached descendants or survive its own SIGKILL under these constraints. H∂: permissions, PID namespaces, process visibility, inherited SIGCHLD disposition, signal scheduling, Python and GNU timeout availability change behavior. Evidence threshold for bounded repair: targeted real-process regressions, injected failed/invalid process tables, actual Chromium cancellation, a new attack proving the leader remains waitable while inspected, and full gate reporting; not universal correctness.

Available and actually used: shell, git, gh, Linux 6.1, Python 3, Node 22, real process groups and an isolated user/mount/PID namespace, Chromium 143, PostgreSQL, Next/TypeScript, ESLint, web search, and the existing gate's oracle prerequisites. No independent agents, independent expert, theorem prover or simulator participated. No external code was copied.

## Frontier
Linux [`waitid` documentation](https://man7.org/linux/man-pages/man2/waitpid.2.html) specifies `WNOWAIT` leaves the child waitable so a later wait can reap it; `P_PID` selects the supervisor's child and `WNOHANG` allows observing exit without blocking. An unreaped zombie retains its PID until reaped. Linux process groups are identified by the group leader's PID, and the group continues while it has members; see [process-group explanation](https://biriukov.dev/docs/fd-pipe-session-terminal/3-process-groups-jobs-and-sessions/). These statements apply within their relevant Linux namespace and do not establish arbitrary descendant containment. The test observes the leader as Z at inspection, but does not force PID wraparound or prove all schedules. The unresolved interface is safe containment and verification when the group can be escaped or processes are hidden, as well as abrupt supervisor death.

## Mechanisms and adversaries
1. **Wait then numeric group kill**: actual old implementation in `f0d2a62`. Local counterexample: leader can be reaped before group signalling; an empty group can be reassigned. New observation test run in an isolated PID namespace failed 0/1 against this old helper because the leader had disappeared before inspection. This detects early reap, not a reproduced PID-reuse attack. Gap: local identity safety.
2. **`kill -0` then group kill**: attacker lets the old last member exit and PID be reused between calls. Existence/permission check and subsequent signal are not atomic. Causal counterexample; local identity gap.
3. **Fixed sleep after leader**: attacker outlives the sleep or group ID is recycled during it. Causal counterexample; no reliable identity or cleanup evidence.
4. **Pin leader with `waitid(WNOWAIT)`**: implemented supervisor. Popen starts a new session; explicit `waitid` observes but does not reap; TERM/KILL and table check occur before `waitpid`. New real observation test 1/1 verifies zombie during inspection and fails on the prior implementation. Attackers: abnormal parent death, incomplete table, descendant escape, SIGCHLD auto-reap and D state; bounded, not general containment.
5. **pidfd for leader**: a stable handle can refer to a process but does not itself identify or signal every member of an escaped descendant tree. Cheapest attack: new session child after leader exit. Not implemented; local group versus tree gap.
6. **delegated cgroup per suite**: could track more descendants if delegation and write permissions exist; attacker migrates out if permitted or parent dies without cgroup cleanup. Requires deployment/permission contract and real isolated experiment; infrastructure gap.
7. **subreaper plus descendant accounting**: adoption may expose orphans but doesn't itself prevent escape or atomic PID reuse, and changes reaping semantics. Cheapest attack: nested detached session and concurrent exits. Not implemented; larger process-management gap.
8. **kill entire PID namespace**: provides broader isolation when a fresh namespace is available and correctly terminated; attacker is an inherited external resource or service outside namespace. Requires privilege/namespace support; infrastructure gap. The namespace used for the old-helper attack and benchmark was a real user/mount/PID namespace, not a simulation.

Rejected misleading results: leader exited therefore descendants exited; signal sent therefore termination completed; one neighboring group survives therefore reuse impossible; `kill -0` success proves stable identity; ps success proves full visibility; empty table means empty group; malformed output accepted; zombie treated as running; D state treated as gone; timeout converted to success; nonzero status hidden; unbounded wait called bounded; PID alone is a tree; detached Chromium test proves all detached children; supervisor SIGKILL considered handled; one Linux version proves portability; synthetic signals replace real tests; shorter cancellation proves whole-gate speedup; process-runner fix claimed as an OS feature promotion.
