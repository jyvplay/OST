## A. Formal contract

An admissible v2 snapshot is bounded JSON with a valid version, timestamp and kind; canonical, unique safe absolute VFS paths; bounded file contents and metadata; valid notes/settings; and a SHA-256 digest over the canonical complete payload. File bytes are UTF-8 or canonical base64. Config snapshots contain editable settings, not documents or notes. A browser verifies the snapshot and requests a destination-dependent preview; an explicit subsequent commit with the same snapshot and destination token runs as one serializable PostgreSQL transaction.

Information model: the browser and server can inspect their respective data, but a checksum is unkeyed and proves no identity; an attacker who can edit a plain bundle can recompute it. Optional PBKDF2/AES-GCM download encryption protects the downloaded file with a user passphrase, but the restored plaintext snapshot reaches the Fusion server. Neither SHA-256 nor a preview token is a signature. The client privacy layer is not an authorization boundary against a malicious script or a direct server caller.

For every valid config snapshot and destination satisfying setting validation and not changing between preview and commit, an acknowledged successful restore changes exactly the permitted, known, unlocked settings and writes their undo history atomically. For every malformed/tampered snapshot, missing consent, stale preview, incompatible destination or transaction failure, it must not report an acknowledged successful restore. An acknowledgement lost during COMMIT has **unknown** outcome, not guaranteed rollback. For failure-free SQL transactions the atomicity claim is bounded to the database rows touched by this implementation, not external side effects or the entire app.

Limits: 64 MiB serialized snapshot/request; 8 MiB per VFS file; 10,000 records per collection; direct-child folder sync only, UTF-8 text ≤1 MiB and ≤5,000 names per side. The request is buffered before its byte count is checked; this is not a streaming memory bound. Local times are actual test-run timestamps. An imported backup is a merge, not an exact disk image or deletion mirror; tasks, contacts, trash, past versions and arbitrary app databases are not in the data snapshot. Folder sync is not backup, recursive synchronization or a cross-process lock.

## B. Outcomes and frontier

- **H+ (supported, bounded):** configuration export, validation, preview, commit, history and live refresh work in this PWA with a running server/database. Evidence: unit, SQL/HTTP, Chromium and fault-injection gates in §H.
- **H− (supported for a different stronger claim):** File System Access `getFileHandle({create:true})` is not an atomic create-if-absent against native apps, and an origin-scoped browser write lock is not an OS-wide compare-and-swap. An unconditional promise of no native-writer collision is therefore not justified by this API alone. This is a platform-interface limitation, not a proof about every conceivable native helper.
- **H∂ (explicit boundaries):** after a lost commit acknowledgement, the transaction may actually have committed; inspect before retrying. Locked/unknown settings are skipped and reported. A browser lacking picker support cannot mount a folder. Strong authentication requires the encrypted envelope and custody of its passphrase; an unencrypted checksum does not provide it.

PostgreSQL documents atomic transactions ([transaction tutorial](https://www.postgresql.org/docs/current/tutorial-transactions.html)). SHA-256 via Web Crypto is an unkeyed digest, not a MAC ([MDN digest](https://developer.mozilla.org/en-US/docs/Web/API/SubtleCrypto/digest)). The File System standard's create flag opens-or-creates, not exclusive-create ([WHATWG FS](https://fs.spec.whatwg.org/)); `createWritable` exclusive mode is not a native cross-process exclusion guarantee ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/FileSystemFileHandle/createWritable)). Chromium OPFS provides real browser handles but is not a picked OS directory ([MDN](https://developer.mozilla.org/en-US/docs/Web/API/File_System_API/Origin_private_file_system)).

Reviewed permissive implementations: Apache-2.0 [browser-fs-access](https://github.com/GoogleChromeLabs/browser-fs-access/blob/main/src/fs-access/directory-open.mjs) and its legacy chooser; MIT [noble-hashes](https://github.com/paulmillr/noble-hashes/blob/main/src/sha2.ts). Their code was not copied: Web Crypto, the browser API and independently written glue were used; the chooser fallback cannot supply persistent writable sync. Reviewed installed Drizzle and [its transaction source](https://github.com/drizzle-team/drizzle-orm/blob/main/drizzle-orm/src/node-postgres/session.ts), [failed BEGIN issue](https://github.com/drizzle-team/drizzle-orm/issues/6114), and [swallowed SQL error issue](https://github.com/drizzle-team/drizzle-orm/issues/6572). The installed version has BEGIN outside the release-protecting block; the independent wrapper covers the **new** backup and conditional-write paths, not every old transaction. The exact remaining local-sync interface is atomic native-file creation and cross-process compare-and-swap.

## C. Negative shapes and modal-shortcut counterexample

The modal shortcut failure is concrete: `Ctrl+F` and `Delete` can propagate from Save-as to a background Slides editor, opening Find behind the dialog or changing saved bytes despite the user believing the modal owns input. `scripts/e2e-tt81.mts` E3 opens the real modal, sends both keys to its input, asserts no Find pane and unchanged file bytes, then verifies normal Ctrl+F after Escape. E5 tests Word Count's focus trap. In the final production environment E3/E5 passed as part of 7/7; `e2e-tt67-input` independently checked its modal/Meta+Q path, 5/5. These are actual browser tests, not an inferred property of labels.

## E. Evidence and repairs

The final selected production gate was executed sequentially against the optimized build with real PostgreSQL: **18 suites, 144/144 cases**. Breakdown: backup format 5/5, HTTP restore 8/8, SQL transaction 5/5, backup UI 6/6, LocalDisk 5/5, new privacy browser suite 3/3, queue 2/2, pointer model 3/3, raw pointer 6/6, forced pointermove fallback 6/6, integration 25/25, privacy transport 12/12, privacy backup 7/7, Writer/office 5/5, privacy E2E 15/15, accessibility 9/9, proxy 7/7, Tabletop 15/15. Separately, the modal/office suite passed 7/7 and input-modal suite passed 5/5, for 156 passing cases across these 20 suite invocations. Full latest result JSONs are in `docs/test-results/`; the compact gate output is reproducible with `scripts/run-all.sh` and the suite names.

The local folder browser tests used real Chromium OPFS handles and IndexedDB reload, not a mock filesystem; they verified preservation of oversized, invalid UTF-8, binary and directory collisions, BOM handling, conflict rechecks, VFS version snapshots and collision-free binary import. They did **not** exercise a native folder picker, OS writers, removable/network volumes or a second engine. Backup HTTP tests injected failure during the second file and second setting update and verified rollback, including history/index. SQL test injected a lost response **after a real commit**, demonstrated that the data existed, and checked that the wrapper returned failure/unknown rather than success or false rollback.

Earlier attempts are material evidence, not erased by passing retries:

- Old production privacy tests were **0/3**: conditional writes reached host SQL in amnesia and created plaintext in locked `/Private`, and LocalDisk was not blocked in amnesia. The new guard blocks those paths; production direct-SQL and UI suites now pass. It does not stop arbitrary direct server calls.
- The first production Writer suite was **4/5** because the footer hid status; wrapping/clipping was repaired, then the full suite passed 5/5.
- One initial privacy run was **13/14**, timing out waiting for the Privacy module; an unchanged rerun and final run passed. Cause of that one-off timeout is unproven.
- An earlier combined gate had raw pointer **5/6**, timing out after overflow. Three immediate reruns passed. The test now synchronizes listener readiness and animation frames; final raw and forced fallback each passed 6/6. The original timeout's cause is not proved.
- The proxy suite initially failed **6/7** with GitHub certificate verification in this test environment. Default Node fetch reported `UNABLE_TO_VERIFY_LEAF_SIGNATURE`, and `node --use-system-ca` returned HTTP 200. A production server started with system CA subsequently passed 7/7. This does not change the application's trust policy or establish a general network fix.
- The full Tabletop suite failed **14/15**: the north card was still projected at approximately 96 × 76 px while the DOM said `data-settled=true`; its final box was 112 × 181 px. The old passive effect published the new pose before clearing the old flag. A MutationObserver on the first committed north pose reproduced `settled=true` on the old build; the layout-effect repair and a block on starting new card drags during pose transition make it `false`. The focused test and full production 15/15 passed; reverting the repair was killed by mutant M20. The old debug observations and delay remain in the test and are disclosed; they can affect timing.
- The first added modal/office suite run was **5/7** because the separate Python oracle environment lacked `pypdf` (E2/E4), not because the modal assertions failed. After installing BSD-licensed pypdf and independently using Apache-licensed PDF.js 5.4 with a real nonblank raster in E4, the suite passed 7/7. PDFium was not substituted for this test: previous evidence shows that it ignores `/UserUnit`. PDF.js incorporated a [UserUnit viewport fix](https://github.com/mozilla/pdf.js/pull/19196). The old `tt81-core` MuPDF-based tests were not rerun by this replacement.

Build, typecheck, `git diff --check`, runner shell syntax and scoped ESLint on new backup/privacy/LocalDisk/transaction code passed. Tabletop lint has one existing image warning and no errors. **Repository-wide lint is not clean:** the measured run reported 182 errors and 18 warnings; Writer and Shell error totals matched their HEAD baselines. This is not a passed mandatory repository lint gate.

## F. Coverage and next test

`docs/LEDGER.md` and `src/data/coverage.json` are generated from 217 **latest saved suite result files from mixed dates**, not one complete run; a suite file is overwritten on a full rerun and can omit prior failures. Authored `full` test tags mean that at least one test author marked a case full; they are not a completeness proof. The 414-row register and counts are therefore navigation aids, not evidence that every feature is Class A.

Highest-information next test: on a disposable real desktop folder, with permission revoked/regranted across a browser restart and an independent native process replacing an empty file between create/open/close, record actual bytes and whether a collision is reported. Until then BK-02/FM-08 cannot honestly be promoted to a general safe native sync/mount. Other open work includes the complete incremental timeline, actual restore drills, distinct general-backup recovery-key custody, hardware-keystore backing, broader privacy boundary enforcement and repository-wide lint.
