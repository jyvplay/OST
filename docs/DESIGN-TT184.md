## Runtime and contract
Available and used: one coding agent, Node 22/Next/TypeScript build and ESLint, Bash, Git/GitHub CLI, Playwright and genuine Chromium 143, disposable real PostgreSQL, Python with independent test-only image and Office libraries, web search and fetch. No independent agents, theorem prover, or simulations were used. Browser/DB tests use one shared exclusive disposable server, not real user data. This is not proof for all devices, engines, networks, or OS features.

Admissible objects: the real Files UI and server file operations, and the gate's actual test-tool environment. Access: local repository, disposable database, real browser, package registries and public standards. Resources: two CPU sandbox, wall time and dependencies outside production; no formal global optimality bound. For drag success, for each exercised source/target sequence in the chosen fixture, there must be an actual native dragstart and drop on the intended paths, followed by the expected server state and byte identity. Cancellation must leave the source in place and retry must succeed. No claim covers all interleavings or screen sizes. Gate success requires all configured suites and prerequisites pass in a complete uninterrupted invocation; individual subsequent passes cannot retroactively make a failed gate pass.

H+: tested Files native gestures and independent oracle setup can work. H−: universal Class-A coverage or Pareto optimality cannot be inferred from these finite checks and no proof or measurement of either is available. H∂: outcomes depend on window geometry, selected rows, directory contents, tool availability, real image codecs, browser and network; these conditions must be specified. Evidence threshold for accepting a change is a production build when product code changes, relevant real-browser/DB attacks, independent oracle checks and explicit disclosure of remaining failures. No global success declaration is made.

## Frontier and candidate portfolio
The [HTML drag-and-drop standard](https://html.spec.whatwg.org/multipage/dnd.html) describes the drag data store and event processing; under its stated event model, data is written at dragstart, the drop target cancels dragover to accept, and data is read at drop. This does not prove an app or a specific browser's scrolling works. [Playwright issue 12599](https://github.com/microsoft/playwright/issues/12599) documents another reported scroll-while-dragging difficulty, not proof of the cause here. Trace in our experiment showed a different source row's native dragstart after target scrolling. Open interface: offscreen-target native drag/autoscroll across real browsers, and truthful density bounds independent of accumulating session data.

1. **Unchanged app + visible native targets**: artifact TT55 maximizes the test window and moves to a point actually inside the empty target; two native gestures, six stress cases with source/drop trace and server hash, synthetic Ctrl copy separately. Proved only in this fixture. Attacker: wrong source after target scrolling, checked per gesture. Gap: offscreen gesture and real native modified-key copy, local but not solved.
2. **Defer selection until dragend**: executable prototype was tried; tested 2/2, but the unmodified app also passed the same maximized tests. The patch was discarded, since benefit was not established and it changes selection timing. Attacker: compare base under identical conditions; gap is causal necessity.
3. **Scrolling while holding native pointer**: causal model: starting the drag before scrolling avoids changing the row beneath a not-yet-started gesture. No implementation retained; verify across clipping/auto-scroll and competing selection state. Gap: local interaction and browser compatibility.
4. **Native cancellation then retry**: new TT184 test in ordinary window starts a real drag, cancels, checks server state and retries with native events; 1 pass within TT55. Attacker: accidental move during cancel or wrong source on retry. Gap: only one layout and small directory.
5. **Explicit oracle dependencies and generated fixtures**: prepare script now explicitly installs oracle packages even with unrelated existing tool manifest, produces genuine independently encoded HEIC and AVIF atomically, and installs msoffcrypto. Preflight opens and decodes both and verifies formats/dimensions. Attacker: syntactically valid JSON with bogus bytes, rejected; a genuine fixture accepted. Gap: decodability is not independent validation of every semantic property or complete dependency inventory.
6. **Density fixture isolation**: observed 19 server-backed root rows after gate and a word counter including offscreen-but-laid-out children; screenshot `.cache/tt184-files.png` was visually inspected. Hypothesis: variable content contributes to cap failures, not proved as sole cause. Candidate: controlled populated and empty fixtures plus actual clipping-aware measurements, without hiding user content. No change adopted because that requires an independently validated revised contract; local interface remains open.

Fifteen invalid substitutes: (1) a successful build as feature proof; (2) passing maximized drag as universal geometry; (3) synthetic Ctrl drop as native; (4) move as copy; (5) a browser event as server durability; (6) matching names as matching bytes; (7) cancellation button as evidence of no mutation; (8) a different source moving as correct source; (9) an installed library as a working independent oracle; (10) a valid JSON header as a real image; (11) clean package metadata as decoded content; (12) tests passed after gate as a retroactive gate pass; (13) hiding results or raising caps as a density fix; (14) a counted register label as Class-A verification; (15) theoretical script parallelism as measured Pareto speedup.
