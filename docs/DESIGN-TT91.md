# TT91 — bounded browser saves, deletion and cooperating races

This is a continuation of TT90, not a claim that the original OS or the requested ten additional Class A features are complete. **New Class A promotions: 0.** The work below is a real, bounded improvement to the web/PWA implementation, tested against Chromium and an **exclusive disposable** PostgreSQL database, not an Android SAF, secure-erasure, native download-manager or physical-device implementation. TT92 contains the later trash work and the latest production gate.

## A. Formal scope and quantifiers

Let `P` be the normalized target path and `D(P) = {P} ∪ {paths with literal prefix P + '/'}`. For successful current-server `purge(P)`, with `P != '/'`, the transaction removes the current database's `vfs_nodes`, `vfs_versions` and file-source `index_docs` rows in `D(P)` and records the audit. SQL `%`, `_` and `\\` in `P` are literal. On a confirmed SQL failure before commit, those row changes roll back together; a lost commit acknowledgement is **unknown**, not proof of rollback. This says nothing about old backups, WAL, replicas, storage remnants or noncooperating actors.

For any current ordinary or conditional VFS writer that uses the shared tree gate, and a participating purge using its exclusive form, the forced tested orderings cannot publish new rows inside a purged tree without that writer either preceding the purge or observing its outcome. Current cache cleanup, ordinary and conditional cache writers and cache-related purge also use the thumbnail gate. These are **cooperative** PostgreSQL advisory locks, not kernel filesystem locks: move/copy, backup restore, some internal operations, older servers and direct SQL are outside the quantifier. TT92 extends participating tree operations to trash/restore and mkdir.

For a private-proxy **Save to Files** action, the requested path is a sanitized basename in `/Downloads`, byte data is the proxied response, and server-side create-if-absent is retried up to 100 names after conflict. A non-2xx or 206 response, actual or declared overflow above 8 MiB, aborted/stalled stream, uninstalled privacy layer, or amnesic session must not knowingly publish a file. Cancellation ends before commit; once commit starts, a lost acknowledgement is reported as unknown. The destination is an **unencrypted server copy**, not `/Private`; the UI states this. Browser-initiated downloads still belong to the browser.

## B. H+, H−, H∂ and frontier

- **H+ (supported evidence):** real bounded stream reading, conditional numbered creation, explicit Files discovery, transactional deletion/history/index removal and the specified cooperating lock interleavings; direct SQL and browser tests confirm the selected rows and bytes.
- **H− (reject):** unconditional overwrite, trusting `Content-Length`, claiming cancellation after a commit starts, calling deletion secure erasure, silently sending bytes to an encrypted store, calling a returned registration a native OS default, or treating one passing performance sample as a general guarantee.
- **H∂ (boundary):** a commit can succeed while its response is lost; offline replay is intentionally disabled; 100 collisions can exhaust retries; arbitrary old/direct/noncooperating writers bypass gates; browser pre-hydration code and direct HTTP are outside the client privacy guard; browser networking and device throughput vary.
- **Frontier:** a complete native queue/resume/download manager, all VFS mutation paths sharing correct locking, crash recovery, secure handling of external copies and a reproducibly passing privacy performance budget across environments/devices.

## C. Independent sources and implementation

[MIT StreamSaver.js](https://github.com/jimmywarting/StreamSaver.js) and [MDN Streams](https://developer.mozilla.org/en-US/docs/Web/API/Streams_API/Using_readable_streams) were reviewed. StreamSaver's service-worker/intermediary design does not fit this server VFS or its privacy contract; the bounded reader and conditional save were independently written. [PostgreSQL advisory locks](https://www.postgresql.org/docs/current/explicit-locking.html), [transaction isolation](https://www.postgresql.org/docs/current/transaction-iso.html) and [WAL](https://www.postgresql.org/docs/current/wal-intro.html), together with the MIT [Artifact Keeper trash service](https://github.com/artifact-keeper/artifact-keeper/blob/main/backend/src/services/trash_service.rs), informed atomicity/cooperation and erasure boundaries; no source code was copied. Test-only PDF.js is Apache-2.0; the oracle uses its public API.

## D. Negative shapes and modal-shortcut failure

Not accepted as success: (1) hidden descendant search hits; (2) orphan saved versions; (3) orphan index snippets; (4) unescaped wildcard paths; (5) deleting the root; (6) partial SQL rollback; (7) independent connections pretending to hold one lock; (8) a lock that omits a participating writer; (9) an old or direct SQL writer represented as covered; (10) secure-erasure claims; (11) overwritten same-name downloads; (12) a dishonest/missing length evading the actual-byte cap; (13) a 206 response treated as complete; (14) silently accepting a broken response body; (15) a cancelled stream publishing partial bytes; (16) save after amnesia without the guard; (17) a lost acknowledgement reported as a definite non-save; (18) unbounded queued replay; (19) credentials or query strings in filenames; (20) a visible modal while keyboard shortcuts still act behind it; (21) a test selecting zero cases; (22) lowering a performance threshold; (23) a historical ledger aggregate called a current gate; (24) fake native device evidence.

The concrete modal failure/detection test is `e2e-tt81.mts` E3: focus is forced out of the Slides Save-as prompt, Tab wrapping and editor/shell shortcuts are exercised, then the saved presentation is independently read. `tt90-modal-mutant.py` removed the editor guard and the shell modal hold separately; **2/2** were killed because Ctrl+F and the global palette respectively opened behind the dialog. An earlier weaker `pop`-only mutant survived; the test and focus trap were strengthened rather than claiming that survivor was killed. This does not prove all modals or keys.

## F. Actual tests, failures and repairs

- Old purge baseline **0/1** left two history rows and one search row after deleting a folder. Repair: purge **5/5**, mutation **4/4**, Chromium confirmation **2/2**.
- Old ordinary-write/purge races **0/2** left no node but an orphan version and new search body. Repair: purge races **4/4**, write/purge lock mutations **3/3**, ordinary-write atomicity **2/2**, write mutations **2/2**. Thumbnail races **6/6**, cache lock mutations **4/4**.
- Download units **10/10** and Chromium/HTTP/SQL **7/7**: the real PyPI response is SHA-256 checked, a concurrent HTTP creator forces a retry, a 10,519,523-byte real package is refused, cancellation and 404 are tested, an actual restart into amnesia interrupts a stalled request, and an intentionally lost response follows a committed write. Download mutations **10/10** killed. The first privacy-transition attempt selected the wrong palette row and failed; the corrected exact-row selector passed. An initial mutation-result parser labelled four assertion failures as crashes; after explicitly recognizing `did not match`, the rerun reported the named assertion failures as killed.
- A fresh 40-suite pre-TT92 production run failed: 38 suites passed, privacy lacked the test-only Python `pptx` dependency and TT81 lacked PDF.js. A subsequent dependency-recovered run failed privacy's unchanged save-performance gate and PDF.js 6's changed cleanup API. The oracle now destroys the loading task and test-only PDF.js is pinned to 5.4.624. A later complete two-suite rerun passed privacy **15/15** and TT81 **7/7** with 57/59 MB/s encryption/decryption and 46.3/54.1 ms host/private median saves. Earlier 35–49 MB/s throughput failures and the separate 39.9/64.5 ms save failure remain real; this is not proof of a performance repair or a full 40-suite pass.
- TT92's diagnostic used 16 alternating measured host/private pairs after warmup, CDP network timings and instrumented WebCrypto. On the pre-TT92 production build, one run measured medians 35.2/48.6 ms, network 32.0/33.8 ms, summed private crypto 3.9 ms. The instrumentation changes timings and the sample is not a replacement for the unchanged performance gate; its result does not identify a proven fix.
- Typecheck and scoped lint passed. Whole-repository lint previously failed with **182 errors and 18 warnings**; no clean global lint is claimed.
