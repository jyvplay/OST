## A. Scope and hypotheses

For each supported, visible browser session with the user opting in, the local context selector uses the available primary-pointer and `screen.isExtended` signals to choose one of the documented profile values without overwriting shared base settings. It applies profile settings only within that tab/session and announces changes. It does not establish which physical display owns the window, guarantee Android desktop detection, or detect policy-hidden capabilities. Browser support, permissions, real hardware and time-to-poll are conditional.

For requests routed through the revised thumbnail service, private paths do not use the shared host thumbnail cache, and lock cancels in-flight private work and revokes managed object URLs. The worker pool has a conservative maximum of two workers, with queues, job identity, timeout, cancellation, idle retirement and a main-thread fallback. These are bounded application-path claims, not a guarantee against hostile scripts, old builds, direct SQL, backups, browser caches, swap, screenshots or media recovery. The explicit cache cleanup removes current matching PostgreSQL nodes, versions and file-index rows; it is **not secure erasure** and cannot erase backups, WAL, replicas or residual media. TT91 subsequently found and repaired one cooperative cleanup/write race; other operations remain outside that lock's guarantee.

**H+**: the bounded selectors, real worker execution, private-thumbnail handling and modal isolation have the test evidence listed below. **H−**: a normal PWA cannot obtain the unavailable Android privileged APIs or prove a physical monitor position merely from an extended-screen bit; this is under the browser privilege model, not a claim about separately installed native software. **H∂**: browser capabilities, policy, device load, OS permissions, storage, concurrent noncooperating writers and physical hardware affect outcomes. All-spec completion and ten new Class A features do not meet the evidence threshold.

## B–C. Frontier and independent implementation

The [Window Management explainer](https://github.com/w3c/window-management/blob/main/EXPLAINER.md) and [MDN `Screen.isExtended`](https://developer.mozilla.org/en-US/docs/Web/API/Screen/isExtended) distinguish a multi-display bit from physical-window placement; CSS [pointer](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/pointer) and [any-pointer](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/any-pointer) describe different devices. The [Apache-2.0 workerpool](https://github.com/josdejong/workerpool/blob/master/src/Pool.js) and [MDN Worker](https://developer.mozilla.org/en-US/docs/Web/API/Worker) were reviewed for bounded queues and termination; the repository implementation was independently written, not copied. PostgreSQL's [advisory-lock documentation](https://www.postgresql.org/docs/current/explicit-locking.html) describes transaction-scoped cooperative locks; Drizzle is an existing Apache-2.0 dependency. The frontier remains native display/ADPF/IME/provider APIs, noncooperating mutations, verified device measurements and residual data outside current database rows.

## D. Negative shapes and modal shortcut

The following are **not** accepted substitutes: (1) changing a status without functionality; (2) treating a browser bit as a physical display identity; (3) claiming a virtual monitor test is a physical hotplug; (4) opt-out behavior masquerading as opt-in; (5) changing shared base settings when a profile activates; (6) exposing profile writes in amnesia as persistent; (7) treating unsupported detection as a positive detection; (8) unbounded workers; (9) a FIFO queue that executes newest first; (10) accepting a stale worker result for another job; (11) reporting retirement without terminating a worker; (12) a timeout that leaves jobs unresolved; (13) caching decrypted `/Private` pixels on the host; (14) allowing an old asynchronous render to publish after lock; (15) merely hiding an image without revoking the object URL; (16) deleting nodes while leaving old versions or index text; (17) advertising row deletion as secure erasure; (18) assuming a transaction-scoped lock constrains raw SQL or other mutation paths; (19) accepting a missing or malformed cleanup confirmation; (20) reading an unbounded JSON request before checking its size; (21) a green test that selected zero cases; (22) a visible modal whose background shortcuts still fire; (23) reporting a previously passing throughput result as current after a failure; (24) lowering a performance threshold to obtain a green run; (25) treating mixed-date ledger totals as one current gate.

The modal failure was concrete: a Save-as prompt could look modal while the Slides editor's Ctrl+F or the shell's palette shortcut still acted behind it. The initial mutation that removed only `pop` survived because the input independently stopped propagation; that was not a successful mutant test. The strengthened `e2e-tt81.mts` E3 forces focus escape, tests Tab wrapping and sends editor/shell shortcuts while the dialog is open, then checks saved bytes. The repair traps focus and preserves both guards. `tt90-modal-mutant.py` killed **2/2** revised mutants: removing the editor shortcut guard opened Find behind the prompt, and dropping the shell modal hold opened the global palette. This does not prove every modal/key combination.

## E–G. Mechanism portfolio and adversaries

| Artifact | Established bounded behavior and attack | Remaining interface |
|---|---|---|
| `context-profiles.ts`, `useContextProfiles.ts` | Input validation, opt-in, primary pointer/extended bit, fallback, visible polling and announcements; malformed storage and unsupported detection tested. | No physical monitor identity, privileged Android mode or immediate hidden-tab detection. |
| `ContextProfiles.tsx`, `DisplaySettings.tsx` | Explicit user selection, profile/base separation, cross-tab and amnesic session checks. | No physical-device verification. |
| `thumbs/worker-pool.ts` | Bounded lazy pool, FIFO, IDs, timeout, crash handling, fallback, cancellation and idle termination; mutated cases fail. | Browser scheduling, memory and worker availability vary. |
| `thumbs/service.ts`, `Thumb.tsx` | Real pixels; private cache bypass and object-URL revocation on lock; stalled-render attack. | Hostile or older clients and other storage layers are outside this path. |
| Thumbnail cleanup route and parser | Explicit bounded confirmation and transaction deleting current nodes/versions/index; oversized, malformed, wrong-origin and amnesia tests. | Not secure erasure; direct SQL and uncooperating mutation paths remain. |
| `thumbnail-cache-lock.ts`, transactional cache writes | TT91 forced four real HTTP/PostgreSQL interleavings and removed each participating lock in separate mutants. | Only cooperating current cleanup, regular writes and conditional writes serialize. |
| Slides/AskHost modal handling | Focus trapping and editor/shell shortcut isolation checked with real Chromium and injected mutants. | All other modals and key combinations are not exhaustively proven. |
| Disposable guards and harness | Refuse destructive privacy tests on detected `/Private` nodes/versions or without explicit opt-in; cleanup owns test paths; race requests settle before fixture deletion. | Preflight is not exclusive access and cannot protect a user database from concurrent writers. |

## H–I. Verification, repairs and failures retained

- ST-09 unit **4/4**, Chromium/CDP **8/8**; thumbnail worker unit **9/9**, private-path **1/1**, public Chromium **5/5**, private Chromium/PostgreSQL **5/5**. The public tests use real browser workers and PNG, SVG, text and WebM fixtures; the private tests verify decrypted pixels and SQL, lock/revocation, cache bypass and cleanup/parser adversaries.
- TT90 targeted mutants **15/15** killed and revised modal mutants **2/2** killed; sources were restored. Full TT81 production suite **7/7**. The old `pop`-only survivor and earlier missing focus trap are not hidden by the later result.
- Before the fix, Chromium exposed a private WebP on the shared host cache and a readable object URL after lock. Later an actual SQL/HTTP interleaving left an orphan version/index after cleanup even though the write returned 200. TT91's cooperative transaction lock repair passed **4/4** interleavings and **3/3** targeted lock mutants; its scope is the participating paths only.
- Earlier production gates failed because destructive suites correctly refused orphan private versions, a GitHub proxy case timed out once, and privacy throughput measured 35–49 MB/s against an unchanged ≥50 MB/s threshold. The orphan guard and test-owned cleanup were repaired and an exclusive fresh database used. A subsequent production run measured **56 MB/s** with host/private median saves **35.4/45.3 ms**, passing the unchanged gates once; earlier failures and environment/load variability remain real, with root cause unproven. A synthetic raw Chromium AES-GCM diagnostic and separate Node timing do not establish a `/Private` speed fix.
- Optimized production build, TypeScript and scoped lint passed. Whole-repository lint previously found **182 errors and 18 warnings**; no clean global lint gate is claimed. The later TT92 52-suite production run exited 1 (51 suites passed; a shallow-clone historical-commit failure in TT67). After fetching the exact historical commit, TT67 alone passed 11/11; this does not turn the failed aggregate run into a pass. See `DESIGN-TT92.md` and per-suite `docs/test-results/`, rather than inferring a current gate from mixed-date ledger totals.
