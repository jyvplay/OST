# TT93 — cooperative VFS transfer, restore and sidecar integrity

## A. Scope, requirements and quantifiers

The user requested that TT92 be finished first, then more of the master specification and **at least ten other genuinely functional Class A core features**, while preserving working behavior, privacy and lightweight constraints. The canonical authority is `Full V2 and V2.1 Specs.txt`, not a register label. This turn implements substantial database-local repairs but establishes **zero** new Class A promotions; the requested ten remain unmet. FM-03 and FM-11 are canonical tier B. MD-03 was corrected from built to partial, not promoted: the PWA lacks Android MediaStore and tested Chromium lacked HEIC capability. FM-18 and PR-01 remain partial; native SAF safe-save is absent.

For a single PostgreSQL database and the current participating server code, each tested move/copy takes an exclusive cooperative tree gate, verifies every source file's stored-string SHA-256, rejects invalid/trash-containing source trees and occupied destination nodes/history/index, and commits current paths, moved history, file search, audit and COMPLETE journal together. Public-VFS photo/recipe moves and copies use the same transaction and reject occupied destination sidecars even when the source has no sidecar. Copy produces an independent current snapshot, not copied source history. Existing live nodes keep their identity and versions across a move. These guarantees apply only to this database and current participating paths; they do not cover old servers, direct SQL, some internal mutations, unrelated services, other databases, native providers, every crash or every interleaving.

File-bearing backup restore takes the same tree gate and, when paths overlap the thumbnail cache, its gate, while retaining serializable validation. A snapshot may become stale while waiting and require a new preview. `dropVersions` and tag writes now participate as shared writers; history removal and its audit share a transaction. All race/trigger tests explicitly require an exclusive disposable database and matching server; the environment variable is not proof of exclusivity.

## B. H+, H−, H∂ and frontier

- **H+**: the named current VFS transaction, checksum, history/search/sidecar collision, selected HTTP/PostgreSQL lock-order and real-browser photo paths have executable evidence. The 16 targeted mutations each caused its named adversarial assertion to fail on the dev server.
- **H−**: a logical `COPYING_TO_TEMP` journal label is not an actual external temporary file or reopen validation; a single subtest does not prove an entire canonical feature; PostgreSQL deletion is not secure erasure; SHA-256 is not source authentication; database-local atomicity is not native SAF or cross-provider atomicity.
- **H∂**: `REQUESTED` is persisted before the data transaction and may remain after a crash; a lost COMMIT acknowledgement is unknown. Advisory locks cover only participants. Restore can abort a serializable conflict. At the TT93 boundary a late sidecar save after a photo move could recreate an old orphan. TT94 adds a cooperative guard for current public Photos saves; unguarded clients remain outside it. Sidecar trash/restore/purge remain separate best-effort actions, and encrypted Private filenames cannot be paired by the server without browser assistance. Old lost history cannot be reconstructed. At the end of TT93 the Photos identity-recipe/rating paths swallowed a sidecar-purge rejection before updating local saved state. The TT93 baseline reproduced both failures; see `DESIGN-TT94.md` for the subsequent repair and its rechecks. Database-wide locking and hashing every file can delay unrelated writers for large trees; no large-tree performance bound has been measured.
- **Frontier**: at least ten additional fully established Class A features; native provider/save semantics, complete crash recovery/undo/pause/resume, atomic sidecars for all operations and Private names, exhaustive nonparticipant races, physical devices and installed-PWA checks, repeatable performance and a clean repository-wide lint gate.

## C. Source review and independent implementation

[PostgreSQL transactions](https://www.postgresql.org/docs/current/tutorial-transactions.html), [explicit/advisory locking](https://www.postgresql.org/docs/current/explicit-locking.html) and [isolation](https://www.postgresql.org/docs/current/transaction-iso.html) informed transaction, lock and stale-snapshot boundaries. MIT [TigerFS](https://github.com/timescale/tigerfs/blob/main/LICENSE) was reviewed, including its [rename integration test](https://github.com/timescale/tigerfs/blob/main/test/integration/rename_test.go) and [history design](https://github.com/timescale/tigerfs/blob/main/docs/adr/012-versioned-history.md); its FUSE/Timescale design is not this PWA's VFS. MIT [SidecarSafe](https://github.com/KanadeK/sidecarsafe/blob/main/docs/RULES.md) treats ambiguous and orphaned sidecars as findings rather than guessing. The public [Maple sidecar issue/PR](https://github.com/zubair-io/Maple/pull/4827) illustrates wrong-attachment and concurrent-save risks; its repository license was not established, so no code was adopted. The work here was independently written, not copied, renamed or memorized from those sources.

## D. Negative shapes and the modal-shortcut failure

Rejected shapes: (1) an overwritten or resurrected trashed source; (2) a tree containing an independently trashed child silently revived; (3) a file used as a destination parent; (4) a destination under a trashed folder; (5) a corrupted child accepted because the root hash matched; (6) an occupied destination history joined to unrelated data; (7) a destination search row overwritten; (8) `_`, `%`, backslash or Unicode paths touching a neighbor; (9) source descendants left in search after a move into Private; (10) a copied tree missing child search rows; (11) a move losing prior versions or stable node identity; (12) an index or journal failure publishing a half-move; (13) a sidecar collision overwriting or misattaching edits; (14) an orphan destination sidecar attaching to an unrelated photo; (15) a sidecar fault committing its photo alone; (16) a sidecar save that wins the cooperative gate being lost by the following move; (17) a history deletion committed while its audit fails; (18) a tag write reporting success on a vanished source; (19) a backup restore bypassing a preceding trash/cache cleanup; (20) a sidecar saved *after* a move claimed to be covered by the earlier ordering test; (21) direct SQL/old-server writes falsely included in the lock quantifier; (22) no selected tests or a crashed mutant counted as killed; (23) benchmark thresholds lowered; (24) physical erasure, native provider access or Class A completion inferred from a PostgreSQL subtest; (25) a visible modal while editor or global shortcuts execute behind it.

`e2e-tt81.mts` E3 forcibly moves focus outside Slides Save-as, exercises Tab wrapping and editor/shell shortcuts and independently reads the saved presentation. `tt90-modal-mutant.py` removed the editor guard and the shell modal hold in separate runs: **2/2** were killed when Ctrl+F and the global palette respectively opened behind the dialog. An earlier weaker pop-only mutant survived and is not relabelled as killed. This is a concrete detection test, not proof of every modal or shortcut.

## E. Six-plus distinct mechanisms / artifacts

| Artifact | Mechanism, adversary | Limit |
|---|---|---|
| `src/lib/server/vfs.ts` transfer | One database transaction, whole-tree checksum verification, literal escaped prefixes, stable identities, moved histories, all child search rows and rollback faults. | Same-database only; no native temp/reopen, resumable journal or full undo. |

Failures included lost history/search/identity, trash resurrection, invalid parents, unverified corruption, partial publication, destination orphans and destructive sidecar collision. The new baseline expanded to **17/17**, transfer races **5/5**, serializable restore races **3/3**, metadata races **4/4**, integration **25/25**, privacy-layer **12/12** and real Photos **8/8** on the dev server. - Backup-restore race baseline **0/3** and metadata/history baseline **0/4** failed before their repairs; reruns passed **3/3** and **4/4**. Source mutation checks on the final transfer/restore/metadata code killed **16/16** targeted mutants.

A 56-suite run reached every selected suite but **did not pass**: `e2e-privacy` failed the save-latency gate at 74.1 ms private versus 45.9 ms host (encrypt 54 MB/s), and I edited the runner while it was executing, causing a final shell parse error and exit 2. A clean 57-suite production rerun completed **56/57, exit 1**: `e2e-privacy` failed its unchanged throughput minimum with **44 MB/s versus 50 MB/s**, so save latency was not measured in that run. ## G. Exact remaining gaps and next test

At least ten requested additional Class A promotions are still outstanding. The PWA cannot itself provide Android MediaStore, native SAF, system-image operations or privileged device APIs. Physical monitors, genuine external-device hotplug, installed-PWA default associations, real native HEIC, independent-device full restore and secure erasure are unverified or unavailable. The next required test is the complete latest production gate with isolated privacy performance, followed by ledger regeneration, a rebuilt static ledger endpoint and preview-host smoke test; continue with forced late-sidecar-save and Private-sidecar pairing tests, crash/unknown-commit experiments, and a large-tree lock/throughput benchmark. Never represent older/mixed-date results as a fresh aggregate pass.
