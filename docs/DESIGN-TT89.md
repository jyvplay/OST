# TT89 — restore drills, PWA launch handling, and honest limits

**The TT89 request for at least ten additional genuinely Class A core features was not met: zero rows were promoted to built in this turn.** BK-05, ST-03, SH-13 and AU-03 remain partial; FM-10 remains a probe. TT89 produced useful implementations and tests, not the requested completion. In particular, a foreground reminder is not unattended scheduling, and opening a host file *into* Fusion is not Android's DocumentsProvider for exporting Fusion files to other apps.

One coding agent used the repository, shell, web-search/page retrieval, Node 22/TypeScript and Next.js compiler, PostgreSQL, Python, Playwright, headless Chromium 143, and axe-core. No independent agent, theorem prover, physical phone, native OS chooser, installed PWA, or human expert review was used. The embedded database and browser dependencies were test-only under `/home/user/tools`, and the database was disposable. An attempted Chromium DevTools PWA install/launch failed: this headless build does not expose the `PWA.install` or `PWA.launchFilesInApp` commands. Chromium tests that call a launch consumer explicitly use **synthetic launch delivery**; their OPFS handles, HTTP, filesystem operations and PostgreSQL are real. This is not evidence of OS registration. The Arena preview hostname was allowed in the dev configuration, but an outbound request to the proxy failed; the proxied browser path has not been independently verified.

## A. Formal scope

Admissible inputs: valid or malformed Fusion v1/v2 bundles, encrypted recovery envelopes selected by a user, browser-provided file handles and `web+fusion:` launch URLs, browser-local health records, and actual database states in a disposable UTF-8 PostgreSQL instance. The browser and server have only web APIs and their existing PostgreSQL privileges; the app cannot inspect Android's app registry or guarantee future browser wakeups. Secrets are not sent in the encrypted archive's credential fields; a **decrypted archive is sent to the Fusion server**, and PostgreSQL temporary tables and indexes may write plaintext to disk. Rollback is not secure erasure.

A bounded drill succeeds only if: for every accepted nonempty archive, validation succeeds; a deterministic bounded sample is actually restored through the shared engine in shadow tables, read back, and PostgreSQL acknowledges rollback; failed or skipped work is not labelled a full pass; no tested production table or sequence changes. An OS file import succeeds only after explicit consent, for at most eight strictly decoded UTF-8 files no larger than 1 MiB each, with a compare-and-create copy in `/Documents` and no overwrite of either the original OS file or an existing Fusion file. In amnesia it must refuse. Bounds and dates are exact, except browser/runtime availability and real time are not guaranteed. These are **bounded PWA contracts**, not the complete native Android, unattended monthly scheduling, all-device, full-archive, provider, or full-OS contracts.

H+ (bounded foreground operations) has direct test evidence. H− (a browser page cannot itself obtain unavailable privileged OS APIs or guarantee wakeups) follows only under the stated browser privilege model, not as an impossibility for a separately installed native service. H∂ (real PWA file delivery, OS association, scheduling, scratch storage and speed) depends on browser, device, permissions, deployment, load and database configuration. No hypothesis about all-spec completion met its evidence threshold.

## B–C. Frontier and sources reviewed

* PostgreSQL temporary tables shadow unqualified tables, while copied serial defaults could still touch permanent sequences; the drill excludes copied defaults and creates local identities. `ON COMMIT DROP`, restricted `search_path`, and an acknowledged rollback do not prove secure erasure or reproduce triggers and foreign keys. [PostgreSQL CREATE TABLE](https://www.postgresql.org/docs/current/sql-createtable.html).
* Restic distinguishes data-reading checks from actual restores and warns that cryptographic key compromise cannot be undone without re-encryption. [Restic design](https://github.com/restic/restic/blob/master/doc/design.rst), [repository checking](https://github.com/restic/restic/blob/master/doc/045_working_with_repos.rst), BSD-2-Clause. Kopia likewise distinguishes repository checks from recovery: [Kopia](https://github.com/kopia/kopia), Apache-2.0. No code copied.
* Browser periodic background sync is limited by support, permissions and browser scheduling; it cannot guarantee a monthly encrypted-file drill: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Web_Periodic_Background_Synchronization_API).
* Manifest declarations alone do not process files: [Chrome PWA file handling](https://developer.chrome.com/docs/capabilities/web-apis/file-handling). `registerProtocolHandler` requests registration; it does not reveal OS defaults or approval: [MDN](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/registerProtocolHandler). Android and Windows guidance was checked against [Android help](https://support.google.com/android/answer/14324187?hl=en) and [Microsoft](https://support.microsoft.com/en-us/windows/apps/change-default-apps-in-windows). The Apache-2.0 [GoogleChrome samples](https://github.com/GoogleChrome/samples/blob/gh-pages/LICENSE) were reviewed, not copied.

The open interface is the real user-selected file and launch/scheduler boundary: physical installed-PWA association, browser consent, repeated OS launches, and a durable separate restore environment must be tested on supported devices; no browser API shown here supplies the unavailable native guarantees.

## E–G. Mechanism portfolio and adversaries

| Mechanism / artifact | Established portion | Strongest local attack and falsification | Remaining interface |
|---|---|---|---|
| Bundle validation, `backup/bundle.ts` | Complete v2 checksum and bounded schema before sampling | Modify metadata/content or manifest; HTTP tests and drill mutant M11 reject | An unkeyed checksum is not authenticity; legacy is partial |
| Stratified deterministic sample, `backup-drill.ts` | File/folder/note/setting caps, reproducible non-prefix selection | Exceed caps or skew toward first rows; health test and M6 | Other records and other backups remain untested |
| Shadow PostgreSQL tables, `backup-drill.ts` | Real shared restore + read-back, private-index exclusion, scratch identities | Inject index leak or missing relation; DB tests, M4/M5 | No production triggers/FKs, separate installation or secure disk erasure |
| Acknowledged rollback, `transaction.ts` | Rollback-only and loss/wrong-tag handling, client disposal; pooled reuse checked | Lost/wrong rollback acknowledgment, SQL fault; DB tests and M1–M3 | No proof of durable-media erasure; other old transactions do not all use this wrapper |
| Foreground calendar health, `drill-health.ts` | Bounded browser-local dates/outcomes/counts; leap-month and exact due boundary | Clock reversal, partial/fail, empty and malformed records; M7–M10 | No unattended job or automatic notification |
| Privacy and consent, `Backup.tsx`, `Shell.tsx` | Explicit local-file consent and plaintext-server warning; amnesic refusal | Cancel/shortcut, secret leak, absent guard; Chromium and M9/M11; backup M12/M13 | Server plaintext, transient files, browser/OS traces are not eliminated |
| Strict protocol parser, `pwa-launch.ts` | Same-origin target and known module, no arbitrary action or extra parameter | Foreign origin, credentials, duplicate/extra parameters, unknown app; unit tests and PWA M1–M4 | Real OS association and all single-instance cases unverified |
| Atomic import, `pwa-file-import.ts` | Strict UTF-8/BOM, type/size bounds, `writeIfUnchanged` and collision retry | Invalid encoding, prototype extension, concurrent writer; PWA M5–M8/M10 | Not a DocumentsProvider, not write-back to original; native selection unverified |
| Capability guide, `DefaultAppsGuide.tsx` | Manual platform steps and actual browser registration request without pretending acceptance | API absent, rejected registration, axe; Chromium guide test | Actual system-default state cannot be queried via this API |
| Test refusal, `tt89-test-safety.mts` | Refuses destructive tests absent opt-in and with trashed/orphaned Private data | Three real DB/child-process attacks; 3/3 pass | Opt-in and preflight do not prevent another process racing test setup; disposable isolation is mandatory |

All mechanisms still have local platform or verification gaps. No mutation test is a mathematical proof; each mutant changes exactly one source string and the runner restores the original in `finally`.

The cause of variation is not established; no performance success is claimed.

Its test now rejects hit points whose *topmost actual target* is an overlay or unrelated control and can record pointer events under `DEBUG_TABLETOP`; the earlier intermittent failure's root cause was not captured and is not claimed fixed with certainty.

On the final production run `e2e-tt55-shell` passed 3/3 and pointer raw and forced fallback passed 6/6 each; the original sporadic pointer root cause was not independently proven.
* The scoped ESLint gate for the new backup/launch/guide modules passed. `Shell.tsx` has the same 5 errors and 3 warnings as its HEAD baseline. Fresh repository-wide `npm run lint` **failed: 182 errors and 18 warnings**. Typecheck, `git diff --check`, shell syntax and the optimized production build passed.
