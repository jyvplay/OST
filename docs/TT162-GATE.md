## Bounded research model
Object: the existing PWA production build and its unchanged gate on an exclusive disposable database with real Chromium and external oracle inputs. Access: repository source, local browser/HTTP/PostgreSQL, checked-in test results, and public documentation; no access to every end-user device or assistive technology. Resources: wall time, CPU, real suite assertions and measured word counts; no new comparative CPU benchmark was conducted. Success threshold for merging this PR: after reviewing main, all mandatory gates pass on the exact production build and changes preserve functionality/privacy; a speed claim additionally needs a controlled before/after comparison at equal fidelity. Quantifier: for the tested build and test environment, all required suites must pass; this does not imply correctness for all environments. H+ a safe repair might satisfy these conditions; H− current build/run fails them; H∂ results depend on data volume, browser and readiness, and bounded gate success is not universal OS completeness. No impossibility theorem or global optimality result has been established.

Frontier: TT161's scroll-to-target repair is supported by a clipped-target attack and the full gate run. The unresolved interface is making the density requirements meaningful for growing data while preserving discoverability and interactions, and proving that the deployed snapshot and source match in the same complete run. W3C's disclosure example (https://www.w3.org/WAI/ARIA/apg/patterns/disclosure/examples/disclosure-card/) describes keyboard and state practices, not proof that a particular application redesign is accessible.

## Distinct candidate mechanisms, artifacts and attacks
These are research candidates, not implemented or verified repairs. The concrete artifacts are their falsifiable contracts below; no candidate inherits trust from the previous gate.
1. **Native disclosure:** group optional routine tools under named summaries while retaining primary actions. Attack: keyboard open/close, focus order, and existing workflows; test visibility and function before/after. Gap: local UI and accessibility validation, not all OS features.
2. **Pagination:** bound displayed routine entries while retaining search and navigation across the complete collection. Attack: delete/disable on a later page, empty last page, large counts; test end-to-end. Gap: local list state and discovery.
3. **Virtualization:** render only viewport rows with logical total and keyboard navigation. Attack: keyboard focus into recycled rows and variable heights; independent accessibility test required. Gap: local but substantial accessibility complexity.
4. **Content aggregation:** compact repeated audit/storage entries into meaningful summaries with drill-down. Attack: loss of individual records or misleading counts; compare to the original complete API output. Gap: local data mapping and interaction.
5. **Deterministic isolated datasets:** measure UI with documented zero/small/large seeded datasets on a disposable database, without deleting application data. Attack: hidden behavior on real growing sessions; compare large-data results to representative live states. Gap: measurement design, not product UX and cannot by itself justify removing existing assertions.
6. **Shared measurement pass:** gather repeated density observations in one browser navigation per app only if the suites' fixtures, readiness, environment and measurement semantics are demonstrably identical. Attack: a state mutation or differing assertion/order between old suites; run old and candidate runners on matched isolated databases and compare every assertion and receipt, wall time and CPU. Gap: equivalence proof and empirical benchmarking; a faster single run alone is not Pareto evidence.

Misleading shapes: DOM presence as visibility; root viewport overlap as scrollport visibility; pending as decoder failure; timeouts as proof of deadlock; extension as encoding; mock decoder as format proof; cached thumbnail as fresh rendering; passing individual test as passing full gate; stale ledger as current evidence; built status as Class A; aggregate receipts as gate success; hiding all controls as usability; raising word caps as product improvement; deleting user data as density repair; sampling one viewport as all-app accessibility; parallel browser tests as guaranteed speedup; wall time alone as Pareto proof. TT161's real offscreen HEIC regression attacks the modal DOM-presence shortcut. The next highest-information test for density is a controlled comparison of empty, moderate and large datasets with a breakdown of fixed chrome versus dynamic rows, coupled with keyboard workflow checks; it must not silently replace the current gate.

No new production feature, Class-A promotion, original graphic, or measured speed improvement was delivered in TT162. The request for 20 promotions and all-app visual review remains unmet; duplicate shell execution and unauthenticated settlement also remain unresolved. The PR should not be merged as a clean, Pareto-superior result on this evidence.
