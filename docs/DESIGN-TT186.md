# TT186 — quota status accessibility and density measurement

## Runtime, contract and outcomes
One coding agent used the repository, Git/GitHub CLI, Node/TypeScript/Next build, ESLint, Bash, Chromium 143, a disposable PostgreSQL-backed shell, test-only independent libraries, and web research. No independent agents, theorem prover, simulator, real assistive technology, or cross-browser verification were used. Delayed/rejected browser estimates were injected as test faults, not represented as real disk data. Two CPUs were available; mutating browser suites use one exclusive disposable DB and run sequentially.

Admissible objects: the existing shared `VolumePanel` and the Files density counter. Access: DOM/accessibility semantics, browser-origin storage estimate, real shell and DB; no physical-disk API. Resource: number of counted words and, for timeouts, event-loop elapsed milliseconds; screen geometry in CSS pixels. Success in scope: for each of the tested Files and Monitor mounts, the existing changing estimate text resides in a pre-existing named status region with explicit atomic updates; its timing and real/unknown distinctions remain intact. For the tested cleanup race, an old mounted panel's late result must not overwrite a newly mounted panel. These finite cases do not imply all AT/browser combinations or OS-grade completeness. Density success would require a declared metric accounting for variable data and clipping, plus adversarial evidence; merely raising caps or hiding data is not that success.

H+: programmatic status and a reproducible clipping counterexample can be delivered. H−: from one Chromium role assertion one cannot deduce actual screen-reader announcement or universal WCAG conformance; origin quota cannot establish physical free disk. H∂: screen reader settings, browser implementations, timing, content and geometry alter outcomes. Acceptance threshold: prepatch failure, production build, changed-file lint, real browser checks in both hosts, temporal/unmount attacks and related regressions; a complete gate is reported as its actual result rather than presumed passing.

## Frontier
W3C [ARIA22](https://www.w3.org/WAI/WCAG22/Techniques/aria/ARIA22) says role=status has implicit polite and atomic semantics and recommends explicit `aria-atomic=true` where complete messages are important because some environments differ; it requires the status container to exist before the message and equivalent context within it. That is a technique, not proof of announcements on a particular AT. W3C [SC 4.1.3](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html) concerns status messages programmatically determinable without focus. MDN [Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API) describes intersection geometry with clipping ancestors and root; geometric intersection is not proof of perceivable text, lack of occlusion, or accessibility. The open interface is robust AT announcement plus a density metric that neither counts offscreen list content as visible nor conceals meaningful chrome/content.

## Mechanism portfolio and adversaries
1. **Named atomic status (implemented):** artifact `VolumePanel` and browser tests; prepatch status-role assertion failed, postpatch tested in both hosts. Attacker: missing/duplicate status or missing atomic flag; tested by role/name/attribute. Gap: live announcement and context under real AT, local.
2. **Timer cleanup guard (existing implementation, new attack):** terminal-pane toggle unmounts/remounts volume, old promise resolves first, new promise later. Browser test checks no old result leaks into new mount. Attacker: stale callback crossing lifetimes; checked in one shell. Gap: every scheduling/interleaving and AT effect, local.
3. **Clipping oracle:** native `IntersectionObserver` on real rows before/after scroll compared to legacy count, artifact `scripts/tt186-density-geometry.mts`. Attacker: rows with geometry but outside clipping region; experiment exercises scrolling both directions. Gap: occlusion, transforms, partial text, inline fragments and other engines; local to metric.
4. **Controlled dataset:** TT185's empty vs 30-file experiment yields 222 vs 509 words, with 18 clipped rows. Attacker: variable file names/journal produce count changes; artifact is executable. Gap: stable representative fixtures and whether chrome is wordy, local.
5. **Exclude all file rows:** counterexample: hides every populated listing, including problematic long filenames and metadata. No patch adopted. Cheapest falsification: include a long visible filename and require it counted. Gap: local but invalid shortcut.
6. **Collapse the mechanics strip:** possible disclosure design preserving explicit access; no implementation this turn. Attacker: hidden focusable elements, inaccessible control, undiscoverable real quota or regressions in keyboard scroll. Cheapest tests: keyboard expansion, AT and geometry; gap local, but not established. See W3C disclosure guidance in TT185.

## Negative space
A build is not user acceptance; a label is not a live region; a role is not an actual spoken announcement; implicit atomicity is not universal AT behavior; initial text is not a later update; a late callback is not always current; an abort is not rollback; a timeout is not cancellation; browser quota is not disk space; a mock response is not a real measurement; geometric intersection is not actual visual perception; an offscreen row is not a missing file; one dataset is not all sessions; a changed cap is not improved UX; a historical register claim is not Class A. Modal shortcut: equating DOM existence or element size with visible text or real measurement. The new geometric test compares live browser intersection at two scroll positions with the old counter, while fault-path tests distinguish held promises from measurements; they do not establish global correctness.
