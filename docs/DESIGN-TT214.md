# TT214: create workspace presets without timestamp revisions

The Routines save button sent `Date.now()` as a revision to an int4 API. A PUT with revision 1760000000000 returned 400 and the pre-patch UI failed to display a saved preset. In the pre-patch browser suite the create race and lost-response checks also failed (0/3); those two checks specified new behavior and are not proof of a pre-existing regression. The original response observer also saw unrelated desktop writes, so the 400 is independently confirmed by the HTTP request, not attributed to that observer.

The new POST operation inserts `preset:<name>` with revision 1 using PostgreSQL's unique-key conflict arbitration. A collision returns 409, never overwrites the existing row, and asks for a different name. This is a deliberate create-only behavior; it does not implement overwrite. Cancellation sends no create. A failed or lost response is reported as unconfirmed, followed by a list refresh, and is not automatically retried. A per-component lock avoids duplicate clicks while the dialog or request is pending.
