# TT230 — density suite coverage hole

## Contract and evidence threshold

Admissible objects are the TT125 literal app/cap pairs and the measurements obtained by visiting those app windows in the disposable real Chromium/server/database environment. The contract for this repair is: for **every** name in the specified 20-name set, the executable array contains one positive finite cap, and the actual suite attempts each visit; after measurements, every exceeded/missing/invalid count is reported. Units are whitespace-separated DOM text tokens under the existing density method, not a validated measure of visual usability. Failure of any one app must not be hidden by success of a majority. This is not the problem of proving all OS features, all screens, real accessibility, or native parity.

H+: the missing array entries and first-only diagnostics can be repaired locally. Threshold: static regression fails before patch and passes after; real Chromium logs show both restored targets visited, with unchanged caps; tests exercise multiple concurrent failures. H−: an array-membership check alone cannot prove the app actually loaded, the word count is correct, or that every state fits. H∂: measured density depends on viewport, asynchronous readiness, and mutable session data. The TypeScript team describes comments as syntax trivia omitted from normal AST nodes ([TypeScript architecture](https://github.com/microsoft/TypeScript/wiki/Architectural-Overview/81dfc8901d53cbc13ea0b9984ce8b260560e2dcd)); this explains why parsing the source instead of searching for strings detects this particular comment failure, but does not itself verify runtime reachability.

## Evidence

The pre-patch AST test failed 1/2: Terminal and SSH were inside a `//` comment after Planner, though their apparent entries were present in the text. A 19-of-20 negative test also rejected a commented target: the modal shortcut fails because a majority can pass while a mandatory rare target is absent. After repair the checker and multi-failure tests passed 3/3. A real Chromium TT125 run listed **Terminal 14/48** and **SSH 61/80** for this fixture. It remained red: Files 375/260. All bounds are unchanged. The new aggregation reports every exceeded target, plus missing/nonfinite readings, rather than exiting on the first assertion. The AST guard is wired into the normal pure gate and is intentionally narrow: it checks a literal `APPS` array, not that arbitrary future refactorings still run its loop. A separately observed browser run provides the limited runtime evidence above.

Direct TypeScript checking also exposed four pre-existing `mechanism` tags outside the harness's `full | partial` type. These were changed to `partial`, matching the existing ledger treatment of non-`full` values; the three changed scripts then type-checked and linted successfully. A post-tag TT125 rerun still visited Terminal and SSH and failed only the Files bound (2/3 assertions). No claim of performance improvement follows: the extra checks and restored app visits add work.

At least these misleading shapes are rejected: a passing build; a green unit test; an AST match in comments; a 19/20 majority; a mounted window; a visible frame; a positive text count; a screenshot; a stale screenshot; a clipped-element count called visible; a cap raised to pass; deleting existing controls; hiding warnings; a synthetic data fixture claimed as real; a passing earlier suite; a fast run missing tests; a register status called Class A; and a zero-exit command without checking its test summary. The 19/20 attack explicitly catches the modal shortcut, not every possible omitted execution.

## Visual and unresolved work

One actual screenshot each was inspected for Files, Routines and Storage. Files devotes substantial space to labeled policy examples, while Routines and Storage display many real test-created entries and duplicates. Removing or concealing functionality, or changing the density caps to manufacture a pass, was not accepted as a repair. Session-data growth and clipping-aware measurement remain unresolved; the next high-information test is a controlled fixture with independently counted on-screen and scrollable text at multiple viewports, including keyboard access and live warnings. No other apps were visually checked this turn. There were no ten Class-A promotions, production-feature claims or measured Pareto speedups. No independent agents, theorem provers, simulators or expert reviewers were used.
