# TT226 — framing advisory and direct opt-in

The server's CSP classification is conservative, not a complete ancestor/source matcher. `csp-restricted` now says the policy needs review instead of asserting refusal. An explicit direct-frame action warns that the destination sees the user's IP and may still block the frame; the action is reversible. A pending probe no longer renders a direct iframe, and both visible split tabs are probed. Proxy-all remains a separate explicit routing mode.

## Evidence and boundary

With Chromium 143, a real HTTP fixture on loopback port 4043 and a separate test-only app server on port 4002, the initial allow/deny cases failed 0/2 before the advisory change and passed 2/2 after. A stronger browser-request counter then exposed a direct request before the probe completed (1/2). This is not a proof for every navigation, frame nesting, or persistence race. The probe itself contacts the destination from the server. Direct mode may persist as part of a tab's saved state; revisit the duration and revocation semantics of consent. Browser enforcement is not bypassed.
