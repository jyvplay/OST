# TT200 — clean up survivors when a gate suite exits

## Model, thresholds and hypotheses
Admissible objects are the Linux gate helper, its `setsid`/`timeout` process group, and real processes launched in an exclusive test environment. Inputs are normal exit, nonzero exit, timeout, SIGINT and SIGTERM, including a same-group child that ignores TERM. Observables: exit code, `/proc` state of named fixture children and whether a separate helper remains alive. Counted resources: signal delivery, one process-table inspection per completed suite, up to 50 polls of 20 ms plus `ps` overhead on cleanup; no speedup is claimed. For each explicitly tested case, the helper must preserve success/failure/timeout codes when cleanup is confirmed, must not report clean success if inspection fails, and must not return while the observed same-group child is runnable or sleeping. This is not a proof for every schedule, process group, UID, kernel, detached session, PID reuse or machine.

Acceptance threshold: real prepatch counterexamples, new real-process tests including a neighboring group and inspection failure, existing cancellation/exit regressions, actual Chromium cancellation and honest full-gate report. This improves the reliability of a test runner, not an OS-app feature or Class-A promotion. Adjacent problems not substituted: detached-session cleanup, database rollback, signal delivery guarantees, cleanup after parent SIGKILL, zombie reaping, OS portability, test speed or full application completion.

H+: a bounded post-exit group kill and inspection prevents the observed same-group survivors. H−: a child can escape into another session or kernel uninterruptible sleep; no group-based helper can guarantee all descendants exit in bounded time. H∂: permissions, `/proc`/`ps` visibility, PID/group reuse and scheduling affect safety and evidence. The helper prints a failure if inspection or signalling fails, and changes a would-be success to nonzero; it preserves an existing nonzero/timeout code and reports cleanup failure on stderr. When interrupted, the signal exit code remains nonzero even if cleanup is unconfirmed.

## Frontier
[POSIX kill](https://man7.org/linux/man-pages/man3/kill.3p.html) specifies that a negative PID targets a process group, subject to permissions, and signal zero checks permissions/existence but does not prove termination; it can fail for either absence or lack of permission. [Linux exit documentation](https://man7.org/linux/man-pages/man3/exit.3.html) describes zombies and notes parent termination does not generally terminate children. Those facts do not prove this script is race-free. No third-party code was copied. The unresolved interface is reliable containment and identity across process exit, PID reuse, inaccessible process tables and escaped groups.

## Six mechanisms and attackers
1. **Wait only for `timeout` leader**: actual baseline 0/3. A leader exits on TERM while its child ignores it, or exits 0/7 while a background child continues; real `/proc` shows S or R after helper exit. Local counterexample.
2. **Kill only leader PID**: causal counterexample is an independently running child; TT200 checks that exact child. Local gap, unimplemented.
3. **Group TERM only**: real child ignores TERM. A clean-looking leader exit does not mean the child stopped. TT200 timeout case falsifies it; local gap.
4. **Group KILL and immediately return**: signal sending does not itself establish the child is no longer executing; the previous gate had intermittent immediate R observations, but this turn's 24 direct SIGINT trials did not reproduce them. Do not assert their cause. Exact post-exit state test is the cheapest attack; local unproven scheduling gap.
5. **Group KILL plus bounded `ps` inspection**: implemented, with confirmed normal status, process-neighbor and failed-inspection tests. Attackers include process-group escape, inaccessible processes, PID reuse, zombie accounting and uninterruptible sleep. These remain outside the bounded observed result; Linux/process-environment gap, not whole OS completion.
6. **Subreaper/cgroup per suite**: design could contain or adopt more descendants, but requires infrastructure or native process management and permission semantics. Cheapest falsification is a child creating a session and checking cleanup. Not implemented; broader portability/infrastructure gap.
7. **Wait a fixed sleep**: a timed delay is not evidence of exit and may waste time or expire while a process remains alive. A TERM-ignoring child and state check falsify it. Local gap.

The modal shortcut is to trust the leader's timeout/exit code as proof of group cleanup. The three actual prepatch timeout/failed/successful exit cases detect it. Other misleading shapes: one child gone but another alive; only testing SIGTERM; checking PID 0 rather than group; killed group but unrelated neighbor harmed; zombie considered active; live D state treated as clean; `kill -0` permission error treated as absence; inspection failure treated as success; timeout changed into success; nonzero status masked; no failure injection; no real browser process; synthetic PID list; PID reuse ignored; escaped session counted as contained; `SIGKILL` assumed immediate; missing `ps` silently ignored; real DB rollback assumed; one run called proof; speedup claimed without measurement; test-runner change called ten Class-A features.

## Actual execution and gaps
Available and used: shell/git/gh, web search, Node/TypeScript, production Next build, ESLint, real Linux processes, actual Chromium 143 and disposable PostgreSQL; the full gate invokes independent oracles where configured. No independent agents, theorem prover, expert, or simulator was used. Baseline TT200 0/3; final targeted TT200 5/5, existing TT178 5/5, TT126 regressions 6/6 and real Chromium cancellation TT179 1/1. One early TT126 invocation without the required disposable flag failed 5/6; rerun with the flag passed. `ps` failure was deliberately injected via a test-only executable, not represented as a real system outage. Two real SIGINT trial batches (12 idle and 12 under two busy loops) did not reproduce the earlier intermittent SIGINT observation; no conclusion about its cause follows. No test proves every descendant or escaped group is stopped. Group-ID reuse between leader exit and signal, hidden/permission-restricted process tables, malicious children, hung kernel tasks and manually killing the helper remain unresolved. Each finished suite now incurs `ps` work; no CPU or latency improvement was measured. No ten Class-A promotions, all-app review or graphic redesign is claimed.
