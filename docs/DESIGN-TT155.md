# TT155 — restored window bounds and keyboard scrolling

## Scope, model, and evidence threshold

Objects: this repository's browser shell, measured desktop rectangle and persisted window state. Inputs include a real server/desktop, desktop dimensions in CSS pixels, and windows with finite integer geometry. The narrow contract is: for each tested nonmaximized window larger than the desktop on either axis, hydration, desktop resizing or unmaximizing fits the oversized axis to the available desk; dimensions and positions on a fitting axis stay unchanged. Partially offscreen windows whose dimensions fit remain possible. In the tested 800×600 browser viewport, pointer and keyboard must reach the Terminal input after restoring, shrinking and unmaximizing. A window within one CSS pixel of the measured desk bottom/right is accepted for browser geometry. For Files, a genuinely overflowing named region must be keyboard-focusable and scroll with the keyboard. Tests sample inputs, not every state or browser. A complete gate requires every required suite to finish without failures; a targeted pass or aggregated ledger is not equivalent.

H+: the sampled problems can be addressed without removing existing window or Files operations. H−: a browser PWA is not proved to implement all native OS behavior, and the available tests cannot establish all features are Class A. H∂: small desktop dimensions, deliberately partial-offscreen windows, background/native hosts, display changes and minimum sizes affect what fitting can mean. A fit discards oversized dimensions rather than automatically restoring them when the display grows. A fitting-sized window intentionally moved partially offscreen can still have inaccessible lower controls. These are explicit limits, not claims of universal accessibility.

Local acceptance threshold, declared for this work: pre-change failures in an independent reducer check and real Chromium; TypeScript and production build; new adversarial viewport shrink/maximize/restore tests; untouched partial-offscreen reducer case; real keyboard scroll test and axe; relevant pointer/layout/app suites. Passing this threshold supports only these bounded changes, not PR-wide merge readiness.

## Causal evidence and changes

With a real 1500×1040 Chromium viewport, an oversized restored Terminal window ended at y=1258.5 while its measured desk ended at y=985. The native input was under the clipped desktop/shelf. The pre-repair reducer tests failed for both restore and desktop shrink. `fitOversizedWindows` is applied during hydration, a real viewport change and maximize/restore. It changes only axes larger than the desktop, respects existing density minimums, and preserves deliberately partially offscreen geometry where window size itself fits. No-op viewport events still return the identical state. This does not prevent a user explicitly resizing or moving a window offscreen; changing that general contract is outside this patch. The measured desk, not a saved display's viewport, supplies bounds.

The real-browser attack starts with an oversized restored Terminal, measures its box, uses native pointer and keyboard input, maximizes and restores, shrinks the browser twice (including while maximized), restores again, and checks the input. The reducer test independently checks width-only/height-only behavior, preserve-partial placement, viewport no-op and maximized restore after shrinking. MDN states `overflow: clip` does not allow programmatic scrolling; clipped focusable content can remain unreachable: https://developer.mozilla.org/en-US/docs/Web/CSS/overflow. Replacing `clip` with `hidden` is not equivalent: it permits focus/scroll to shift the desktop and regress the shell's title-bar behavior.

Full layout testing also exposed axe `scrollable-region-focusable` for Files mechanics in Business/Art. A new browser test failed before repair because the scroll region lacked tabindex; it now checks actual overflow, native keyboard focus and End-key scrolling. The named section now has `tabIndex=0`. The axe layout suite passes. A separate stale dock test expected Core always to be folded; the actual plan exposed Core directly while other groups folded. The test now uses either real UI route and retains the magnification, geometry, focus and off-switch checks.

## Candidate mechanisms and adversaries

1. Fit oversize only at restore/display change: executable reducer and Chromium tests; attack maximized restore after shrinking, one-axis-only and partial windows; sampled tests pass. Gap: saved preferred size is not recovered on growth; local geometry issue.
2. Clamp every move/resize: would also prevent intentional partial placement; counterexample is the explicit partial-window test. Gap: preservation of existing behavior, global window-policy issue; rejected.
3. Change desktop clip to scrolling: programmatic scroll may shift title bars; documented CSS semantics above. Attack: focus a low control and check other window title positions. Gap: global layout/focus interactions; rejected without that matrix.
4. Put shelf behind windows: may cover shell controls and change stacking; counterexample is overlapping maximized windows. Attack every layout and overlay. Gap: global chrome accessibility; rejected.
5. Resize only test fixtures: does not repair users' restored geometry. Counterexample: pre-repair real browser bounding boxes show actual clipped input. Gap is the original user-facing problem; rejected.
6. Add keyboard focus to the scroll region: executable native End-key test and axe checks; attack genuine overflow and actual scrollTop. Gap: screen-reader and other-browser verification; local accessibility issue.

Fifteen misleading substitutes: a reducer pass without a browser; a browser pass without measured bounds; a force click; a fake scroll; no-overflow keyboard test; ignoring maximized restore; a larger viewport only; truncating content; changing shelf z-index without accessibility checks; hiding the shelf; altering test coordinates only; increasing density ceilings; assuming a fixed dock grouping; a screenshot without interaction; and ledger totals presented as a completed gate. The common shortcut—shrinking the test fixture only—fails to protect restored user geometry, detected by the oversized-restore browser test.
