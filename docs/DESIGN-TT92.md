# TT92 — truthful trash, restore, and coverage boundaries

## A. Request, scope, and quantifiers

The outstanding instruction is to complete original-spec functionality while preserving existing behavior, privacy and lightweight constraints, including **at least ten other genuinely Class A core features**. TT92 establishes **zero** new Class A promotions: the inspected FM-03 and FM-11 are canonical tier B, FM-18 and PR-01 remain partial, and no native SAF safe-save is claimed. Canonical requirements live in `Full V2 and V2.1 Specs.txt`; register/test tags alone are not proof of complete specification coverage.

For one exclusive disposable PostgreSQL database, the current server, and a tested path tree, the participating current write/mkdir/trash/restore/purge operations use a cooperative advisory gate. A tree operation atomically updates the selected current rows, versions where applicable, search entries, journal and audit according to its operation. Trash groups retain the deletion root, preserve earlier independently deleted groups, reserve deleted paths and restore only the selected group. A legacy row whose group is null can be restored individually; its original group cannot be reconstructed. These are **database rows**, not physical disk erasure. The tested lock coverage does not establish universal isolation against older servers, direct SQL, nonparticipants, backup restore or move/copy on the pre-TT93 build.

The test-only Photos fixtures come from independently generated images and pinned third-party corpus objects. `TOOLSDIR=/home/user/tools node scripts/corpus/fetch-tt54.mjs` can rehydrate and Git-blob-verify the three pinned objects after a sandbox reset without overwriting a conflicting local file. The exif-samples README says contributed images use CC BY-SA 4.0; the fixtures remain outside the application and repository, and redistribution requires attention to attribution/share-alike terms. Their availability and the browser's ability to render real files do not establish support for every camera, codec or physical device. All destructive, trigger and role-permission tests require explicit opt-in and an exclusive disposable server/database that the operator has verified match; the opt-in is not itself proof of exclusive access.

## B. H+, H−, H∂ and frontier

- **H+**: the named trash/restore, wildcard-neighbor, transactional fault, search and cooperative race paths have real HTTP, PostgreSQL and Chromium evidence. The current browser save checks actual streamed bytes and conditional creation. Classification policy caps an incomplete feature at partial-tested even when one subtest says full.
- **H−**: treating a subtest as the whole feature; claiming native SAF, Android/system privileges, secure deletion, crash-proof cross-device restore, complete Class A promotions, universal locking or a throughput repair from one passing sample.
- **H∂**: historical trash-group metadata already lost cannot be recovered. Lost commit acknowledgement is unknown; old servers/direct SQL/noncooperative code may bypass locks; SQL deletion cannot erase WAL, backups, replicas or physical remnants; browser/native-device access and measurements vary.
- **Frontier**: complete spec-level features and ten additional Class A promotions, atomic/serialized move/copy and backup restore, full destructive/restore concurrency coverage, true native save and external filesystem semantics, repeatable performance on relevant devices, and a clean whole-repository lint gate.

## C. Independent source review

The [Freedesktop Trash specification](https://specifications.freedesktop.org/trash/latest/) describes original paths and deletion times; this PostgreSQL implementation is not a Freedesktop implementation. The MIT [sindresorhus/trash](https://github.com/sindresorhus/trash/blob/main/index.js) and [rtrash](https://github.com/HaoZeke/rtrash), and [PostgreSQL locking and isolation](https://www.postgresql.org/docs/current/explicit-locking.html), were reviewed for collision, transactions and cooperative locking. Code was independently written rather than copied. [PostgreSQL WAL](https://www.postgresql.org/docs/current/wal-intro.html) bounds deletion claims. Test-only PDF.js is Apache-2.0 and pypdf BSD; independent rendered-page checks do not turn a browser into a native OS.

## D. Negative shapes and modal-shortcut failure

The following are not success: (1) stale search descendants after trash; (2) overwriting a trashed file; (3) silently reviving an old child when its parent is deleted; (4) restoring below a still-trashed parent; (5) merging null legacy groups; (6) wildcard `%` or `_` matching a neighboring tree; (7) deleting root; (8) publishing a partial transaction after an index fault; (9) orphaning versions or snippets; (10) claiming a shared advisory lock covers nonparticipants; (11) counting physical erasure from SQL deletion; (12) a false-positive ledger promotion from a full-tagged subtest; (13) native SAF claimed from Postgres snapshots; (14) cancellation after publication represented as certain; (15) overwritten same-name downloads; (16) a committed request with a lost response reported as certainly unsaved; (17) a missing browser fixture treated as a pass; (18) a failed generator's first output mistaken for the complete set; (19) a test crash or zero selected tests counted as a mutation kill; (20) a modal that remains visible while shell/editor shortcuts act behind it; (21) reducing an unchanged benchmark threshold; (22) mixed-date ledger totals represented as a fresh gate; (23) a synthetic PWA launch represented as native association; (24) deleting unknown user data to satisfy a test.

`e2e-tt81.mts` E3 deliberately moves focus outside the Slides Save-as prompt, exercises Tab wrapping and editor/shell shortcuts, then reads the saved presentation independently. `tt90-modal-mutant.py` removed the editor guard and shell modal hold separately; **2/2** were killed by Ctrl+F and the global palette opening behind the dialog. A prior weaker `pop`-only mutant survived; it is not retroactively called killed. This detects the named failure, not every modal/shortcut combination.

## F. Verification, observed failures and repairs

- The original TT92 48-suite gate did not finish: 39 passed, `e2e-tt54` crashed at incomplete fixture setup, subsequent privacy/crypto/backup, 16/16 privacy, diagnostic and safety checks passed before sandbox reset. It is **not** a passing aggregate gate.
- In the fresh exclusive database the pinned JPEG, TIFF and PDF objects were retrieved from their specific GitHub commits and verified by Git blob hashes. Photos fixture and media generators ran with independent Python tools. The first isolated Photos rerun failed **7/8** because `tsx` injected a `__name` helper into a Playwright browser callback without serializing that helper. Removing the nested arrow fixed the test harness; rerun **8/8**, browser download **7/7**, safety **3/3**. These are actual browser/HTTP/SQL tests, not simulated app features.
- A later **52-suite production run exited 1**: 51 suites passed and `tt67-input` failed **10/11** because this shallow checkout lacked historical commit `2edf699`. Fetching the exact commit, without changing branches, let the isolated suite pass **11/11**. Bootstrap now fetches it if absent. The failed 52-suite run is not relabelled as passed; a later complete gate is required. That run included TT92 trash **11/11**, trash races **6/6**, browser Trash **2/2**, ledger audit **4/4**, ledger policy **2/2**, Photos **8/8**, privacy **16/16**, and TT81 **7/7**.
- On that same production run the unchanged privacy gate passed once at **55/55 MB/s** encrypt/decrypt and **32.7/44.0 ms** host/private median saves. The optional instrumented diagnostic measured **29.4/47.2 ms**, network **23.5/31.8 ms**, private crypto **3.9 ms**. Prior slower samples and the absence of a demonstrated performance fix remain relevant.
- Earlier targeted TT92 trash mutants killed **13/13**; download mutants **10/10** and modal mutants **2/2**. These are historical targeted results, not fresh results from the 52-suite production run. No automatic assumption is made about all unrun suites.
- The production build passed. Repository-wide lint had previously failed **182 errors/18 warnings**; a fresh global check is still needed. The exact saved test JSON is per-suite and may have different timestamps.
