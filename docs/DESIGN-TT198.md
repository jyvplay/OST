# TT198 — Files type-ahead recovery after a miss

## Model, threshold and hypotheses
Admissible objects are an actual Files pane with a finite sorted/filtered visible option list, a focused option, selected paths, and the in-memory type-ahead buffer. Access is via delivered unmodified keydown events and DOM focus in a production Next app backed by a disposable PostgreSQL VFS. The resource is the existing O(n) prefix scan over shown names; reset adds constant work, and no speedup is claimed. For each tested sequence: a prefix with no visible match must not move focus or selection, and the next typed character within 700 ms must start a fresh prefix; successful multi-character prefixes and repeated-character cycling must still work. Success is quantified over these fixture sequences, list/grid and the tested filter, not all browser/keyboard/IME/AT states or all filenames. Acceptance threshold: a real prepatch counterexample, patched production build, browser tests including attacks against successful prefixes and selection, lint, affected regression tests and transparent full-gate results. This does not establish Class A.

H+: clearing only a failed buffer allows the next character to search without changing successful matching behavior. H−: if no key event is delivered, no browser-only algorithm can navigate from it; immediate reset also cannot preserve every possible future extension under all Unicode/case-folding transformations. H∂: focus leaving the listing, filtering, IME composition, locale, Unicode normalization, long lists, timing and browser/OS delivery may alter the result. Separate problems not substituted: search-as-filter, opening files, selection, screen-reader compatibility, column navigation, arbitrary Unicode matching, test performance, and whole-OS completeness.

## Frontier
[W3C APG listbox guidance](https://www.w3.org/WAI/ARIA/apg/patterns/listbox/) recommends type-ahead, especially over seven options, and rapid multiple characters for a prefix. It does not specify this app's no-match reset or prove accessibility on real AT. No external source implementation was imported. The open interface is the app-specific no-match policy and its effects on focus, selection, input methods and user expectations.

## Portfolio and strongest attackers
1. **Retain the failed prefix until timeout**: real baseline 0/3: z then b never reaches beta/briar. Cheapest falsification is the actual fast keyboard sequence. Local failure.
2. **Clear on every key**: would destroy multi-character search (`b`, `r` must locate bravo). The new suite tests that. Local counterexample; unimplemented.
3. **Fallback to current character immediately on a failed longer prefix**: can unexpectedly jump to a different item when a user mistypes a second character. A `b`, `z` sequence with an unrelated z-named file is a causal attacker. Not implemented; user expectation unresolved locally.
4. **Wait for 700 ms or require Escape after a miss**: already available behavior, but baseline shows it requires extra time/action rather than immediate recovery. Local gap.
5. **Clear buffer only after no match**: implemented; actual postpatch browser tests cover initial miss, failed longer prefix, selection preservation, successful multi-character search, cycling, list/grid and filtered results. Remaining interface includes Unicode extension/locale and real AT/IME; local repair only.
6. **Replace keyboard navigation with filter input**: existing filter changes the visible set and moves focus to a different control, so it is not equivalent to keyboard focus navigation. The existing real filter feature plus filtered-results test are artifacts; gap is behavioral, not a solution to the whole OS.

Modal shortcut: clearing on every printable character appears to fix misses but destroys successful rapid prefix sequences; `b` then `r` test detects it. Misleading shapes include focus movement without preserving selection; valid prefix broken; repeated key stops cycling; no-match selects a row; failed letter retained; first miss tested but failed multi-character prefix not tested; hidden results matched; sort order ignored; filter text mutated; list-only testing; grid-only testing; real keys substituted with direct state mutation; timeout accidentally elapsed; no-wraparound; shortcuts intercepted; background focus mistaken for option; UTF-16 normalization treated as universal Unicode proof; Chromium on Linux presented as cross-platform; synthetic composition presented as real IME; a green narrow test presented as Class A; full gate failure hidden. This is an adversarial list, not a claim that all are proven absent.

## Execution and limitations
Used shell, git/gh, web search, Node/TypeScript production build, ESLint, Chromium 143 and a real disposable PostgreSQL database; independent gate oracle tools are used where gate suites invoke them. No independent agents, theorem prover, expert review or simulator was used. Baseline real browser: 0/3 (list, grid, filtered results). Patched production build targeted run: 3/3. Failed prefix is cleared *after* the miss; its last character is not retried by itself. Real IME, other browsers, locale-specific matching, accessibility technology and user preference for this policy are unverified. No ten Class-A promotions, all-app visual review, original graphics or measured speedup is established.
